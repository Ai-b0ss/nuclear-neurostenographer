## Что было проверено на момент составления

- Sonnet отчитался о последнем `de722e6` с зелёным эмуляторным Android/ASR UI и 20-минутном тесте на более раннем commit. **Это не физический смартфон**.
- Повторение говорящих из маленьких актёрских клипов — PASS, но **DER на естественных русских записях NOT_SCORED**, качество наложения голосов неизвестно.
- [Рецензия на PR #9](https://github.com/Ai-b0ss/nuclear-neurostenographer/pull/9#issuecomment-6585040904) выявила потенциальную несогласованность foreground service: ViewModel может начать запись без подтверждения запуска службы; уведомление обещает «остановить», но лишь открывает Activity. Это **code-review risk**, не воспроизведённый баг; нужны негативные сценарии Android 14+/35.
- В PR #11 разработан и прогнан в GitHub Actions инструмент для арифметически и по идентичности сопоставимых сравнений моделей. Его тесты **синтетические**; реальные выигрыши моделей не измерены.
- Публикация APK ограничена review лицензий/no-TTS native и приёмкой телефона. Не возвращать GPL/TTS в стандартный runtime ради удобства.

## Единый формат отчёта следующего агента

```text
Дата/задача:
Исходный branch/commit, чьи worktree/PR не изменены:
Затронутые файлы/новый PR:
Реально выполненные тесты (команда, CI URL, commit, PASS/FAIL):
Проверенное устройство и условия (или NOT_RUN):
Что выяснилось о качестве/памяти (или NOT_SCORED):
Какие гипотезы остались открыты:
Риски и возможный откат:
Следующее измеримое действие / ответственный:
```

Не подменять блок «реально выполненные тесты» текстом из чужой заметки. Не исправлять исходный исторический PASS/FAIL задним числом. Не приписывать участникам согласованные обязанности только по предложению Opus.

## Непринятые решения и вопросы к организаторам

- Окончательное официальное ТЗ, способ сдачи, критерии оценки, демонстрационное устройство и требования к длительности аудио.
- Можно ли использовать собственный заранее написанный код: пользователь сообщил, что **можно**, но у нас нет ссылки на письменное правило. Проверить по опубликованным условиям/ответу организатора.
- Какая лицензия и форма передачи полной APK+моделей допустима для командного закрытого тестирования и/или публичного релиза.
- Будут ли тестовые записи с перекрытиями, смешанными каналами, тишиной, 3–4 говорящими и спецтерминами.
- На каком смартфоне доступна реальная приёмка; учитывать Android версию, свободное место, ABI и ограничение энергосбережения.

**Порядок работы:** прочитать код и свежий HEAD → выбрать один проверяемый риск → воспроизвести или честно отметить невозможность → внести минимальное изменение в своей ветке → запустить CI + реальный сценарий → сохранить evidence → PR review. Не создавать новую платформу агентов, если нужна всего одна исправленная функция.

## Правила совместной работы с агентами

- Sonnet — Android-интеграция/CI; Opus — критический аудит и измеримые альтернативные модели; GPT — независимая проверка/документы/координация. Это **предлагаемое распределение**, не команда агентам без отправки им сообщения.
- Не использовать пользовательский Chrome/Claude Desktop с видимым управлением без разрешения и без проверки возможности фонового способа.
- Не вымещать личные и приватные переписки в открытый репозиторий. Связанные GPT и Claude источники индексированы в [CONVERSATION_SOURCES](CONVERSATION_SOURCES.md).
- Не делать force-push и merge рабочих веток других агентов, пока не проверены последствия.

Приоритет для любой новой сессии: **сначала реальное устройство и рабочий результат; параллельно — научно честное сравнение кандидатов; затем — улучшения на основании измерений.**
