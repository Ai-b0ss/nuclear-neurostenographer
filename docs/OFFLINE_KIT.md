# Офлайн-комплект установки (APK + модели)

Комплект — это папка из трёх файлов с проверкой SHA-256: `app-debug.apk`, `gigaam-v3.zip` (≈225 МБ), `diarization.zip` (≈46 МБ). После установки приложению интернет не нужен: в манифесте нет разрешения INTERNET, а модели лежат в приватной папке приложения.

**Статус:** комплект и скрипты проверены тестами и в CI на эмуляторе. Установка на физический ARM64-телефон — `NOT_RUN` ([PHONE_ACCEPTANCE.md](PHONE_ACCEPTANCE.md)). APK и веса не публикуются: проект учебный, комплект предназначен для команды; лицензии и уведомления ([RUNTIME_LICENSES.md](RUNTIME_LICENSES.md)) остаются в репозитории и в приложении. Runtime — только закреплённый no-TTS (SHA-256 `771fda6a…c1c8`), исходный GPL/TTS-вариант не используется.

## Что нужно на ПК
- **Чтобы поставить готовый комплект на телефон:** только Python 3.8+ и `adb`. Папка комплекта самодостаточна (проверено запуском из чистой папки вне репозитория). `phone_kit.py` сам ищет adb (опция `--adb ПУТЬ`, переменная `ADB_PATH`, PATH, Android SDK, пакет Python `adbutils`, копии `adbutils` в окружениях других программ). Ничего не устанавливается и PATH не меняется; на этом ПК найден adb 36.0.0 из такой копии.
- **Чтобы собрать комплект:** Python 3.11+, `gh` (авторизован, нужен для закреплённого runtime и способа B), около 1 ГБ места.

## 1. Получить APK
**Способ A — на этом ПК (проверен).** В репозитории уже лежит локальный тулчейн (`.local/build-tools`: JDK 17 и Gradle 8.9, `.local/android-sdk`: SDK 35), поэтому ничего ставить не нужно:

```bash
python tools/build_local_apk.py
```
Скрипт подтягивает закреплённый runtime без TTS (SHA-256 проверяется), запускает тесты ядра, собирает `app/build/outputs/apk/debug/app-debug.apk` и прогоняет `check_apk.py` (разрешения, ARM64/x86_64-библиотеки, соответствие runtime). Кэш Gradle лежит в `.local/gradle-home`. Сборка занимает 2–3 минуты (первая дольше из-за загрузки зависимостей). Локальный APK и CI-сборка имеют одинаковый размер (50 989 367 байт), но разные SHA-256 (отладочный ключ подписи у каждой среды свой).

**Способ B — GitHub Actions.** Короткоживущий артефакт (виден, пока существует, репозиторий публичный):

```bash
gh workflow run build-apk-kit.yml --repo Ai-b0ss/nuclear-neurostenographer --ref feature/long-recordings -f confirm=PRIVATE-USE-ONE-DAY
python tools/offline_kit.py fetch-apk
```
`fetch-apk` проверяет SHA-256 и сразу удаляет артефакт.

## 2. Собрать комплект
```bash
python tools/offline_kit.py assemble --apk .local/apk/app-debug.apk
```
Скрипт скачает модели по закреплённым ревизиям (если их ещё нет), проверит каждый файл, создаст `.local/kit/` с `SHA256SUMS.txt`, `KIT_MANIFEST.json` и `phone_kit.py`. Повторная проверка: `python tools/offline_kit.py verify .local/kit`.

## 3. Установить на телефон (по USB, без выбора ZIP в интерфейсе)
На телефоне: «Для разработчиков» → «Отладка по USB». Затем в папке комплекта:

```bash
python phone_kit.py wait      # ждёт телефон и объясняет, чего не хватает (кабель, отладка, разрешение)
python phone_kit.py install
```
`wait` опрашивает adb до появления телефона и по состоянию (нет устройства / не разрешено / offline) пишет конкретное действие, затем запускает `check`. `check` проверяет архитектуру (нужна arm64-v8a), версию Android (≥ 8), свободное место (≥ 1,5 ГБ) и ОЗУ, и напоминает включить авиарежим. `install` сверяет SHA-256 файлов комплекта, ставит APK, кладёт оба ZIP в папку приложения `Android/data/ru.neurostenographer.app/files/kit/`, а приложение при запуске само проверяет файлы внутри ZIP по закреплённым хэшам, устанавливает обе модели и удаляет ZIP. Результат отображается на экране приложения («Комплект установлен…»).

Если телефон запрещает запись в `Android/data` по adb, `phone_kit.py install` сам кладёт ZIP в `Download` и подсказывает, какие кнопки нажать. Модели можно и вручную поставить кнопками «Установить модель ZIP» и «Установить модели говорящих ZIP».

## Ошибки установки
| Что видно | Причина и действие |
| --- | --- |
| `Kit rejected: … checksum mismatch` | файл повреждён при копировании; пересоберите комплект |
| «Мало места для … нужно около N МБ» | освободите место; ZIP остаётся в папке и устанавливается при следующем запуске |
| «gigaam-v3.zip: … Файл оставлен в папке комплекта» | ZIP не прошёл проверку; прежняя модель не затронута; скопируйте комплект заново |
| `NOT_RUN: adb not found` / `expected exactly one authorized device` | нет adb или телефон не подтвердил отладку |

## Размеры и память
APK ≈ 51 МБ (arm64-v8a и x86_64; по данным apk-inspection.json CI). Во время установки нужно место под ZIP, промежуточную копию и (при замене) прежнюю модель; приложение проверяет запас заранее. На эмуляторе пиковая память: приложение ≈ 612 МиБ (загрузка модели ASR), процесс диаризации ≈ 455 МиБ (в разные моменты); на телефоне не измерялось (`phone_kit.py monitor`).
