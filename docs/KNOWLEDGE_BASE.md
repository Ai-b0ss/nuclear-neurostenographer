# База знаний проекта · читать первой

**Нейро-стенографист / Nuclear IT Hack 2026**

Эта база фиксирует **замысел и аргументы** из переписки тимлида с GPT и Claude, а также **факты разработки** из кода и CI. Она предназначена для команды, следующих агентов, технического review и подготовки защиты. Это не копия личных чатов и не официальное техническое задание.

**[Полная консолидация обсуждений и проверок](CONTEXT_RECAP_2026-11-03.md)** — исходная постановка, A/B/C и joint A+C, конкретные результаты Sonnet/Opus, проверенный C2 Android emulator, ограничения, открытые задачи и порядок продолжения.

**[Независимое исследование MOSS / VibeVoice](JOINT_A_C_EVALUATION_2026-11-03.md)** — отдельная исследовательская дорожка, чтобы не потерять единую архитектуру A+C; критерии сравнения, реальные источники и запрет подменять неиспытанное готовой интеграцией.

**[Дистилляция и русскоязычный pruning](DISTILLATION_GATE_2026-11-03.md)** — отдельный R&D Gate 0 для проверки учителя, данные Granary-v2, условия обучения и ограничения Android. Дистилляция пока NOT_RUN.

## Если у вас 3 минуты

**[Паспорт проекта](PROJECT_CHARTER.md)** — русскоязычная офлайн-стенография на Android; CORE + A (слова) + C (говорящие), опциональный B (проверка); пользователь должен понимать ошибки и иметь возможность исправить результат. Два параллельных пути: стабильное демо и независимое исследование сильных моделей.

**[Реестр решений](DECISION_REGISTER.md)** — какие направления приняты, какие пока гипотезы, почему не переносим 30B на обычный телефон как P0, какие ошибки GPT и Opus уже исправлены.

**[Передача проекта](PROJECT_HANDOFF.md)** — что делать прямо сейчас, какие проверки нужны до хакатона, как не мешать соседним worktree и каким должен быть отчёт следующего исполнителя.

## Принцип достоверности

- **Идея/решение** ≠ реализованная функция.
- **Есть в коде** ≠ успешно на смартфоне.
- **CI x86_64 PASS** ≠ ARM64/авиарежим/нагрев PASS.
- **Актёрский holdout** ≠ независимая естественная русская беседа.
- **Нет эталона** → DER `NOT_SCORED`, а не ноль.
- **Рекомендация Opus/GPT/специалиста** ≠ доказанная модель-победитель.

Если поздний эксперимент опровергает решение, добавляйте датированную запись с доказательствами, а не стирайте историю.

## Как обновлять

1. Для продукта и архитектуры: править [PROJECT_CHARTER](PROJECT_CHARTER.md) только после явного изменения стратегии и обновления [DECISION_REGISTER](DECISION_REGISTER.md).
2. Для исследований: добавить фиксированные данные и результаты в [RESEARCH_PROGRAM](RESEARCH_PROGRAM.md) / связанный PR; неизвестные результаты оставлять неизвестными.
3. Для фактической разработки: обновлять [PROGRESS](PROGRESS.md) вместе с SHA/CI и точным устройством.
4. Для новых диалогов GPT/Claude: добавить дату, тему, решения и ссылку в [CONVERSATION_SOURCES](CONVERSATION_SOURCES.md), **не публиковать приватную переписку**.
5. Для передачи задач: изменять [PROJECT_HANDOFF](PROJECT_HANDOFF.md) и сверять его с последними PR и branch SHA.
