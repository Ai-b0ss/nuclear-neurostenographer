# Приёмка на физическом ARM64-телефоне

Статус: **NOT_RUN**. До выполнения этой процедуры нельзя утверждать, что приложение работает на телефоне. Результат эмулятора x86_64 телефоном не считается ([PROGRESS](PROGRESS.md)).

## Что нужно
- Телефон Android 8+ с ARM64 (`adb shell getprop ro.product.cpu.abi` → `arm64-v8a`), ≥ 2 ГБ свободного места, лучше 6+ ГБ RAM. Запишите модель и версию Android (желательно отдельные прогоны на API 34/35).
- ПК: Python 3.8+ и `adb` (находится автоматически, см. OFFLINE_KIT.md); репозиторий для самой приёмки не нужен, достаточно папки комплекта.
- Согласие участников на запись собственных голосов. Записи в репозиторий не коммитить.

## Подготовка
Сборка комплекта и установка описаны в [OFFLINE_KIT.md](OFFLINE_KIT.md): `phone_kit.py check` (ABI, Android, место, ОЗУ), затем `phone_kit.py install` (SHA-256, APK, модели без выбора ZIP). Включите **авиарежим** и выключите Wi-Fi/Bluetooth до всех замеров; в манифесте нет INTERNET (проверено `apk-inspection.json`).

## Драйвер Windows (HONOR/HUAWEI)
Если `phone_kit.py` пишет, что телефона нет, а в диспетчере устройств виден «HDB Interface» или «ADB Interface» с жёлтым знаком (Code 28), не хватает драйвера. Официальные драйверы Huawei (`hw_goadb.inf` и `hw_gohdb.inf`, класс «Android Phone», подпись «Microsoft Windows Hardware Compatibility Publisher») ставятся вместе с HiSuite (consumer.huawei.com) либо уже стоят; репаки и «универсальные» сборки не использовать. Проверка в PowerShell:

```powershell
pnputil /enum-drivers | Select-String -Context 0,6 "hw_goadb|hw_gohdb"
Get-PnpDevice -PresentOnly | Where-Object InstanceId -match 'VID_12D1' | Format-Table Status,Class,FriendlyName
```
Нужно, чтобы у всех узлов `VID_12D1` статус был `OK`. Важно: драйвер для интерфейса **HDB** (подкласс 0x48) ещё не означает, что adb увидит телефон. adb работает только с интерфейсом **ADB** (подкласс 0x42), а он появляется на телефоне лишь при включённой «Отладке по USB». `adb devices` не показывает эмуляторы как телефон: `phone_kit.py` их игнорирует.

**HONOR 10X Lite (Magic UI):** «Настройки → О телефоне» → 7 раз нажать «Номер сборки»; затем «Настройки → Система и обновления → Для разработчиков» → включить «Отладка по USB»; разблокировать экран, переподключить кабель и нажать «Разрешить» (отметить «Всегда разрешать с этого компьютера») в запросе RSA.

## Сценарии (каждый — минимум 3 повтора, фиксировать PASS/FAIL)
| № | Сценарий | Критерий |
| --- | --- | --- |
| 1 | Запись 2 человек A–B–A, 2–3 минуты, тихая комната | Есть русский текст, A и B различаются, A возвращается как A, время реплик разумно |
| 2 | То же с шумом и перебиванием | Перекрытие помечено, говорящий не выдумывается |
| 3 | Импорт WAV и MP3 на 5 и 20 минут | Нет ошибки таймаута декодирования; записать время импорта |
| 4 | Запись 20 минут | Остановка по лимиту, WAV сохранён, обработка завершается |
| 5 | HOME во время записи, затем возврат | Уведомление «Идёт запись»; запись продолжается; `adb shell dumpsys activity services ru.neurostenographer.app` показывает `isForeground=true` |
| 6 | Блокировка экрана на 1–2 минуты во время записи | Запись продолжается или явное предупреждение в приложении; WAV не пуст |
| 7 | Отказ в разрешении уведомлений (Android 13+) | Запись работает; без падения |
| 8 | Отказ в микрофоне | Понятное сообщение, нет «призрачной» записи |
| 9 | Убить процесс диаризации: `adb shell pkill -f :diarization` во время обработки | Распознавание завершается без говорящих с предупреждением |
| 10 | Мало места на диске | Понятная ошибка, прежний результат цел |
| 11 | Экспорт TXT/JSON/SRT и проверка файлов на ПК | файлы открываются, время не пересекается, `speaker_id` в JSON согласован с TXT/SRT (инструмент: `tools/verify_transcript_exports.py`, формат вызова смотреть в файле) |

## Автоматический сбор
- Во время сценариев: `python phone_kit.py monitor --minutes 25` пишет `phone-monitor.json` (пик PSS приложения и процесса `:diarization`, температура и заряд батареи раз в секунду).
- После каждого сценария: `python phone_kit.py scan` ищет ANR, падения Java/native и убийства приложения и процесса диаризации в logcat и DropBox (тот же детектор, что в CI).
- После экспорта в Download: `python phone_kit.py exports --prefix transcript` забирает TXT/JSON/SRT и проверяет их согласованность.

## Измерения
- Пиковая память: во время обработки `adb shell dumpsys meminfo ru.neurostenographer.app` и для процесса `:diarization`; фиксировать максимум PSS каждого.
- Время: секунды ASR и диаризации для записи известной длины → RTF = время / длительность.
- Нагрев/заряд: `adb shell dumpsys battery` до и после 20-минутной обработки (температура, уровень).
- Качество: WER/cpWER по размеченному эталону ([BENCHMARKS](BENCHMARKS.md)); без эталона писать `NOT_SCORED`, не ноль.
