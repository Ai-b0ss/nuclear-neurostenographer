# Плавный прогресс распознавания длинного аудио — 08.11.2026

## Изменение

- UI больше не показывает только скачки между пятиминутными блоками: AudioProcessingClock на базе SystemClock.elapsedRealtime() экстраполирует положение по фактически измеренной скорости обработки.
- UI обновляет временные отметки и индикатор каждые 250 мс, не запускает ASR в главном потоке и не читает аудио ради анимации.
- После первого завершённого речевого блока скорость калибруется по времени обработки; далее обновляется сглаженно (0,55 старой скорости + 0,45 нового замера). Цифровая тишина не используется для калибровки.
- Отметка не превосходит последнюю секунду ещё не завершённого блока. При достижении границы показывается «Завершаю текущий фрагмент, уточняю время».
- Оценка оставшегося времени не является гарантией срока, может меняться при длительной речи, тишине и разном числе говорящих.

## Ограничения

Новые функции не исправляют независимую проблему длинных записей: в TranscriptionViewModel.recognizeLong() говорящие между блоками намеренно сохраняются как null, пока нет обоснованного сквозного сопоставления. Оценка времени основана на ранее измеренной скорости, а не на точном прогнозе будущих фрагментов.
