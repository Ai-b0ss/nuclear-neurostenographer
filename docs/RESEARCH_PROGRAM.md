# Программа Speech ML-исследований и критерии интеграции

**Версия:** 2026-11-02. Это **рабочие гипотезы и метод**, а не таблица уже измеренных моделей. Для конкурсной ветки ничего автоматически не меняет.

## 1. Сначала ответить на проверяемые вопросы

- Достаточно ли нынешней GigaAM v3 CTC для естественной русской речи, включая короткие и эмоциональные реплики?
- Насколько надёжно текущее pyannote+ERes2Net сохраняет IDs при A–B–A, 3–4 спикерах, шуме и перекрытии?
- Даст ли Nemotron 3 Diarization выигрыш, который оправдывает новую native integration, память и лицензионные ограничения?
- Может ли более качественный ASR e2e / multilingual / Nemotron 0.6B решить реальные ошибки, не замедлив доступный телефон?
- Нужна ли дополнительная обработка B/overlap, или лучшая пользовательская проверка даёт больше пользы за доступное время?

Нельзя ответить на это по model card или зелёной сборке. Нужны один набор входов и независимая разметка.

## 2. Исследовательская матрица

| Код | Кандидат | Этап | Цель / контроль |
| --- | --- | --- | --- |
| A0 | GigaAM v3 CTC INT8 (текущая) | **Baseline, Android** | Нулевая точка качества, скорости и устойчивости |
| A1 | GigaAM v3 e2e RNN-T | ПК → ARM64, если работает | Словесная точность и пунктуация |
| A2 | GigaAM Multilingual 220M | ПК → ARM64 при выигрыше | Компактная альтернативная модель |
| A3 | Whisper / whisper.cpp | ПК и только отдельный мобильный эксперимент | Независимый ASR-контроль; не считать автоматически правильным эталоном |
| A4 | Nemotron 3.5 ASR 0.6B | ПК → ARM64 при выигрыше | Сравнение WER и затрат |
| C0 | pyannote segmentation + ERes2Net threshold 0,8 | **Baseline, Android** | Текущая диаризация |
| C1 | Nemotron 3 Diarization ONNX/LiteRT | ПК → ARM64 | Сильная гипотеза по overlap и устойчивым ID |
| C2 | Nemotron INT8 | ПК → ARM64 | Меньший размер/память, потеря качества относительно C1 |
| J1 | MOSS Transcribe-Diarize | ПК, Android пока не доказан | End-to-end система A+C |
| O1 | VoxLock после выявления overlap | R&D в отдельной ветке | Восстановление именно потерянных слов при пересечении |
| O2 | DiCoP | Исследование feasibility | Conditioned ASR, не лёгкий шумодав |

Каждая строка — **кандидат**, а не задача интегрировать всё. Сильные модели можно запускать на ПК для оценки или обучения студента, но результат на сервере не заменяет локальный Android inference.

## 3. Наборы данных: происхождение, право использования, ограничения

Источники ниже пересказаны из исследования Opus от 02.11 и диалога GPT. Их доступность, лицензии и качество разметки нужно перепроверить **перед скачиванием/публикацией**.

| Источник | Возможная роль | Что обязательно установить |
| --- | --- | --- |
| [DataHive Russian Conversations sample](https://huggingface.co/datasets/datahiveai/russian-conversations-sample) | Естественные двухканальные созвоны, кандидат на первоначальный R | Есть ли доступное аудио, неизменный commit, права, настоящие ground-truth слова/время (Opus утверждает, что транскриптов нет) |
| [ru-book-mix-10h](https://huggingface.co/datasets/mexus/ru-book-mix-10h) | Разнообразие говорящих, RTTM, шум/overlap stress | Природа смеси, реальность говорящих, ограничения оценки и лицензия |
| [synthetic-speech-diarization-ru](https://huggingface.co/datasets/ivkond/synthetic-speech-diarization-ru) | Размеченные синтетические регрессии | Корректность текстов/таймкодов, происхождение озвучки, утечки в обучение |
| [notebooklm_rus](https://huggingface.co/datasets/AigizK/notebooklm_rus) | Длинные синтетические двухголосые записи | Условия некоммерческого использования, достоверность разметки |
| [DAI-ASR-I18N](https://huggingface.co/datasets/davidai-labs/DAI-ASR-I18N) | Независимый тест естественного разговора | Gated access и права; не обходить ограничение |
| [ESpeech podcasts](https://huggingface.co/datasets/ESpeech/ESpeech-podcasts) | Дополнительный корпус при наличии прав | Доступ, license, полнота разметки |
| [Granary-v2](https://huggingface.co/datasets/nvidia/Granary-v2) | Потенциальное сырьё для ASR/последующей дистилляции | По утверждению Opus, в основном манифесты, аудио отдельно; нет готовых ID спикеров |
| Собственные разговоры команды | **Финальный независимый контроль L** | Добровольное информированное согласие, локальное хранение, разметка независимым участником |

**Не выдавать** подготовленные из одного датасета актёрские клипы за несмещённую оценку обычного совещания. Знакомство модели с данными/сценариями обучения может быть неизвестно: прямо записывать это ограничение.

### Разделение набора

- **R — разработка**: несколько десятков минут разнородной русской речи с эталонами, можно итеративно улучшать.
- **L — закрытая контрольная выборка**: 2–4 живых человека, записанные на смартфон, часть с наложением и шумом. Заморозить до окончательной проверки. Ни в Git, ни в облачные CI не загружать.
- **S — стресс**: 20 минут, длинное ожидание, короткие реплики, повторы, сильный шум и перекрытие. Стресс не является автоматически метрикой качества.
- **A — дополнительный внешний контроль**: только если право доступа и независимая разметка подтверждены.

## 4. Единый протокол оценки

Для каждой записи и системы закреплять:
- SHA-256 **оригинального** аудиофайла, источник, права, длительность, каналы, версия эталона, идентичный способ сведения каналов;
- commit/revision модели, tokenizer, native runtime/AAR/ABI, точный код и настройки, Android/ПК, холодный или повторный запуск;
- эталонные слова, известные говорящие и отдельные интервалы активности. ASR chunk times **не могут заменять RTTM-эталон**;
- WER, cpWER, **DER с правилами collar/overlap**, ошибка количества говорящих, A–B–A, ошибка текста внутри overlap; отдельный показатель ложных слов на тишине;
- RTF со строго одинаковыми границами замера, peak memory **всех процессов в один момент**, запас RAM, CPU/тепло/батарея, crash/timeout, offline/flight mode;
- нарушения: отсутствие слов, unknown speakers, падение модели, нулевая память при ошибке — не скрывать и не считать «идеальным результатом».

Для текста WER считать с одним нормализатором. Для DIARIZATION желательно иметь DER при collar 0 мс и, отдельно, 250 мс; overlap включён/отключён явно. Нельзя сводить оценки разных протоколов в единую таблицу без пометки. Долю error по аудиоклипам можно оценивать доверительным интервалом, если набор достаточен.

Существующий [score_transcript.py](../tools/score_transcript.py) рассчитан на WER/cpWER/DER, но не сертифицирован NIST/MeetEval. Сверить на контрольных примерах с [MeetEval](https://github.com/fgnt/meeteval) и [dscore](https://github.com/nryant/dscore) до использования баллов в публичной защите.

Независимый [PR #11](https://github.com/Ai-b0ss/nuclear-neurostenographer/pull/11) добавляет `tools/compare_model_trials.py`, тесты и [формат манифеста](https://github.com/Ai-b0ss/nuclear-neurostenographer/blob/research/model-comparison-gate-20261102/docs/MODEL_COMPARISON.md). **На 02.11 это отдельный DRAFT, не часть базовой ветки.** Пока этот PR не интегрирован, использовать его явно по ветке исследования, не изображать наличие файла в текущей.

## 5. Граница между исследованием и решением внедрить

Сначала оценить C0 vs C1/C2 (диаризация), A0 vs A1/A2 (ASR). Затем при необходимости A4/Whisper/J1. Проверять модели на том же корпусе; менять только один компонент за раз, затем тестировать систему в целом (cpWER может измениться от сдвига границ ASR).

Предлагаемые Opus численные «go/no-go» вроде 10–15% улучшения и RTF ≤1 — **внутренние ориентиры для обсуждения**, не критерии организаторов и не статистическая гарантия. Для конкурсной замены минимально необходимы:
1. **Измеренный прирост на независимой русской речи**, без критической потери на шуме, overlap, коротких фразах.
2. **Проверенный Android ARM64** с установкой, 5 последовательными успешными запусками, авиарежимом и разумной памятью/нагревом.
3. **Чистая лицензия** выбранных весов, native runtime и способа распространения.
4. **Нулевой откат** уже работающих пользовательских сценариев записи/импорта/экспорта.
5. Прозрачные сведения об ошибках и контрольное тестирование после merge.

Если условие не выполнено, сохраняется baseline и эксперимент остаётся R&D.

## 6. Отложенные направления после хакатона

- Дистилляция 30B → компактный student на русском; teacher можно запускать на внешней машине только на разрешённых данных. Само наличие мощной модели не делает псевдометки независимой истиной.
- Pruning/MoE и идея «оставить только русский». Языки распределены по общим весам, поэтому вырезание «английских весов» не является прямой операцией. Нужны отдельная гипотеза, обучение и тест на языковом дрейфе.
- Дополнительный B для исправления имён и специальных терминов, hotwords, подсказки от пользователя.
- До часа записи при потребности пользователя и доказанной работе на устройстве.
- Более удобное прослушивание реплик, исправление и объединение говорящих, история проектов; продуктовая функция может стать важнее очередного 0,1% WER.

## 7. Минимальная форма результата эксперимента

```text
Вопрос:
Baseline / candidate (модель + commit + sha256):
Записи и эталон (права, SHA, число/типы говорящих):
Устройство / OS / ABI / режим без сети:
Условия (collar, overlap, нормализация, холодный запуск):
WER / cpWER / DER / unknown / RTF / peak memory:
Сценарии PASS и FAIL (включая реальные ошибки):
Изменение относительно baseline на тех же файлах:
Цена интеграции, лицензии:
Вердикт: интегрировать / опционально / отклонить / пока данных мало
Подтверждение: код, команды, CI, логи, ссылки на хеши
```

**Главная дисциплина:** выбор технологии является следствием проверяемого результата, а не интуиции GPT/Opus. [Реестр решений](DECISION_REGISTER.md).
