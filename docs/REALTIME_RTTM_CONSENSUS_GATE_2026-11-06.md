## 1. Подтверждённые причины прежнего высокого DER

`tools/realtime/error_atlas.py` воспроизводит оригинальный DER по границам в миллисекундах, проверяя SHA-256 WAV и независимо сохранённого reference. Инструмент отдельно вычисляет энергию PCM в 10-мс окнах. **Энергия не является детектором речи**; метка «тихо» не доказывает тишину, а RTTM нельзя использовать во входе модели.

Проанализированы 15 исходных host-C2 прогонов для syn3, syn4, ABA, overlap, ABAB, return-pause и short-tail. В итоговом syn3 из 9047 мс ошибок пропуска 8415 мс приходятся на PCM тише −35 dBFS; в syn4 из 19990 мс — все 19990 мс. Это свидетельство грубости исходной TTS-разметки и возможных беззвучных интервалов; подтверждения реальной ошибки модели в каждом из этих интервалов нет.

На внешнем RTTM-тесте `rec_0437` с четырьмя голосами найдена **другая, настоящая** ошибка: финальный C2 ошибочно ставит `spk0` вместо `spk2` на отрезках 8,399–10,210 с и 10,769–11,771 с. Итого 2813 мс confusion; пересматриваемый FAST в этих отрезках метку определяет правильно. Задача уже не сводится к неточным TTS-границам.

## 2. Дополнительный корпус и защита от подгонки

Источник: [mexus/ru-book-mix-10h](https://huggingface.co/datasets/mexus/ru-book-mix-10h), синтетическое смешивание русскоязычных аудиокниг, RTTM (разметка временных интервалов говорящих), CC-BY-4.0. Это **не** реальный разговор и не эталон стенограммы: WER/cpWER = `NOT_SCORED`.

Использованы три примера для разработки (по 1 записи на 2, 3 и 4 голоса): `rec_0150`, `rec_0300`, `rec_0437`. После фиксации алгоритма и его SHA-256 `817d2ae79a0a1a6c83dc7dbfbdcbae4b7d73a7a9b68fc2e5c3e594fda3f04730` случайным детерминированным правилом выделен другой набор из 6 ранее не использованных записей, **без общих идентификаторов дикторов** с набором разработки, по две записи на 2/3/4 голоса. Список, overlap fractions и правило выбора: `.local/ru-book-mix-holdout/frozen-selection.json`. Данные сохранены локально; веса и приватный звук в Git не помещаются.

Финальный алгоритм не получает ни RTTM, ни текстов эталона, ни результатов метрик. Для временного соответствия offline speaker slots применяется `SpeakerIdentity.align` по максимальному перекрытию времени двух предсказаний. Затем интервалы, где предварительный FAST уже определил говорящих, **сохраняют** FAST-метки; OFFLINE дополняет только интервалы, в которых FAST не определил ни одного. Оба входа — результаты собственных C2 проходов одной аудиозаписи.

Проверка 10 *development* сценариев показала отсутствие ухудшения DER по сравнению с действующей финализацией. На отдельном holdout:

| Holdout | Голосов | Старая финализация DER | Кандидат DER |
|---|---:|---:|---:|
| rec_0259 | 2 | 3,974% | 3,490% |
| rec_0129 | 2 | 10,758% | 10,758% |
| rec_0388 | 3 | 4,183% | 4,164% |
| rec_0345 | 3 | 3,305% | 3,305% |
| rec_0528 | 4 | 2,957% | 2,957% |

Взвешенный DER по 314 663 мс reference-speaker-time: **4,8347% → 4,7295%**, относительное снижение ошибок **2,18%**, все числа голосов сохранены, ухудшений на отдельных записях не обнаружено. Это ниже планового порога **15%** — нет основания автоматически включать механизм для пользователей. Gate = `GO_FOR_ANDROID_EXPERIMENT_ONLY`.

## 3. Реализация без изменения обычного поведения

Добавлены `SpeakerConsensus.kt`, модульные тесты `SpeakerConsensusTest.kt`, независимый `speaker_consensus.py`, host scorer и воспроизводимые скрипты подготовки данных. В `RealtimeSession` механизм вызывается **только** если `RealtimeOptions.consensusExperimental == true`. Значение по умолчанию `false`; обычный `RealtimeService` не передаёт этот флаг, значит продолжает прежний `global-offline-final`.

Инструментация отдельного applicationId `ru.neurostenographer.app.realtime` получает `--consensus-experimental` через `tools/realtime/phone.py` → Android instrumentation argument. Запись не публикуется вовне, raw PCM остаётся на устройстве. Политика носит явную пометку `dual-pass-preview-first-final-fill-experimental` в `provenance.speaker_source`; метрики содержат `speaker_disagreement_ms` и `speaker_offline_fill_ms`. Реализация работает списком событий (без полной матрицы для часового аудио).

## 4. Физический HONOR: сравнение на том же PCM

HONOR DNN-LX9, Android SDK 29, A3 GigaAM + C2 Nemotron INT8, полностью offline, paced feed, финальный APK и тестовая APK установлены с контролем SHA-256. В каждой строке baseline и экспериментальная версия обработали **одинаковый PCM SHA-256**, использовали один pinned runtime и завершились `PASS`.

| Сценарий | Голосов | DER без эксперимента | DER с экспериментом | Compute RTF эксперимента | ASR токены |
|---|---:|---:|---:|---:|---|
| rec_0150 | 2/2 | 5,170% | **5,003%** | 1,029 | 132/132 совпали |
| rec_0300 | 3/3 | 6,101% | **6,062%** | 1,027 | 145/145 совпали |
| rec_0437 | 4/4 | 13,767% | **8,491%** | 1,016 | 128/128 совпали |

В rec_0437 confusion снижена с 2813 до 20 мс (по RTTM); `miss_ms` 4608 → 4557. **Относительное снижение DER 38,3% лишь на этой конкретной четырёхголосой записи**, не общая гарантия качества.

Проведён отдельный регрессионный прогон **нового APK с выключенным флагом** на rec_0437. Результат: `PASS`, `consensus_experimental=false`, **DER точно 13,767%**, токены совпадают, `provenance.speaker_source` остался `global-offline-final`. Это проверяет отсутствие незапрошенной смены алгоритма.

Собственные измерения: `rec_0437` с экспериментом `speaker_disagreement_ms=3590`, `speaker_offline_fill_ms=180`, `finalization_ms=9934`, sampled PSS `1007547 kB`. `compute_rtf` на этих минутных примерах **1,016–1,029**, **целевое ≤1 не достигнуто**. Разницу в latency/RTF между одиночными последовательными прогонами нельзя считать доказательством ускорения; температуры и нагрузка могли отличаться.

На всех трёх записях сохранены количество и порядок нормализованных ASR токенов; экспортные файлы JSON/TXT/SRT проходят независимую проверку. WER/cpWER не оценивались ввиду отсутствия word gold.

## 5. Найденный и исправленный дефект проверки экспорта

При сравнении запись с повторяющимся коротким текстом `—` изначально дала false FAIL. Источник — **валидатор** `tools/verify_transcript_exports.py`: он выбирал первое совпадение одинакового текста в TXT и при сравнении следующих меток времени ошибочно отклонял правильный файл. Исправлено на перебор всех совпадений с проверкой правильного интервала. Добавлен `tools/realtime/test_export_duplicate_body.py`, который принимает настоящий дубль и отклоняет намеренно испорченное время второго совпадения. Производственные TXT/SRT/JSON не менялись.

## 7. Статус и следующий рабочий блок

**Эксперимент готов, по умолчанию выключен.** Цель P0 — независимо локализовать ошибку и проверить её на новом корпусе — достигнута. Получено конкретное улучшение на четырёхголосом примере, но обобщённый эффект на 6-entry holdout мал. Производственный GO = **нет**: target ≥15% improvement на независимом holdout не выполнен; compute RTF ≤1 не выдерживается; реальная разговорная речь с точной human-gold разметкой и лексический overlap пока не проверены.

Следующий блок: (1) собрать согласованный русский естественный диалог с точной RTTM + текстовой разметкой, (2) отдельно диагностировать пропуски коротких реальных ответов и наложенной речи, (3) уменьшить compute RTF под 1 на ARM64 без деградации качества, (4) оценить gated consensus на более разнообразном holdout и только тогда принимать решение о включении по умолчанию.
