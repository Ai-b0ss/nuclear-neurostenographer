# Эксперимент: глобальные голосовые метки для длинных записей

**Дата:** 11 ноября 2026. Отдельная ветка feat/global-speakerbook-20261111
от origin/main (459773f). Основной релиз не меняется.

## Текущая QA-реализация: Nemotron C2 + TitaNet Small (11.11.2026)

**Предыдущая попытка с 512-мерными внутренними признаками C2 больше не
подключена к работающему пути.** На HONOR она дала один повторяющийся
глобальный ID между двумя разными исходными разговорами; отдельная ручная
разметка личностей отсутствовала, но это достаточная причина не выпускать
алгоритм как надёжный.

Действующий эксперимент, только при флаге globalSpeakerBook=true:

1. Nemotron C2 определяет интервалы говорящих в пятиминутных блоках;
   GigaAM A3 независимо распознаёт текст, таймкоды ASR сохраняются.
2. TitaNetVoiceProfiles накапливает только целиком покрытые 40-мс
   участки, где C2 видит ровно одного говорящего, до 16 секунд
   сигнала для каждого локального ID. При менее чем 3 секундах
   сигнала профиль отсутствует.
3. Отдельная TitaNet Small ONNX (192-мерные эмбеддинги) вычисляется
   sherpa-onnx 1.12.20, встроенным в прежний runtime Android ARM64.
   Веса не добавлены в APK; загружаются только из изолированной
   QA-папки приложения после SHA-256 проверки.
4. Вес модели nemo_en_titanet_small.onnx: 40 257 283 байта,
   SHA-256 ad4a1802485d8b34c722d2a9d04249662f2ece5d28a7a039063ca22f515a789e.
   Источник: официальный выпуск sherpa-onnx с меткой
   speaker-recongition-models. По README Сквора лицензия Apache-2.0.
5. GlobalSpeakerBook сравнивает нормализованные векторы с ранее
   наблюдавшимися группами. Текущие параметры cosine >=0,84 и
   margin >=0,07 **не являются вероятностями и не откалиброваны
   по независимому русскому корпусу**.
6. Без модели, при ошибке чтения, короткой/неоднозначной речи и
   конфликте групп глобальная метка не придумывается: остаётся
   Block N / Speaker K. Время, текст ASR и метки перекрытий
   не меняются.
7. IPC из отдельного процесса диаризации допускает до 8 профилей
   по 192 элемента и валидирует длину/значения. Фатальные ошибки
   виртуальной машины не перехватываются как обычный отказ
   необязательной модели.
8. Только QA application ID с суффиксом .speakerbookqa.
   В обычном приложении флаг отключён; обычный порог длинного
   режима >20 минут, в QA он >5 минут для воспроизводимых испытаний.

**Измерено на HONOR 10X Lite / Android 10 / ARM64:**

- Повтор исходного двухголосого клипа после 5-минутной границы:
  PASS, 2 глобальных ID присутствуют в обоих блоках; 8 фрагментов,
  110 416 мс обработки, RTF 0,298.
- Два разных исходных разговора: PASS негативного контроля,
  2 ID в первом, 3 новых ID во втором, **общих ID нет**;
  21 фрагмент, 142 476 мс, RTF 0,338. При старом C2 варианте
  один ID совпал между источниками.
- Модель недоступна: PASS, 0 голосовых профилей, сохранены
  8 фрагментов, все ID вида Block N / Speaker K;
  после теста файл TitaNet восстановлен.
- Шесть аудиовырезок, 192-мерные эмбеддинги, 4,29 с на телефоне:
  схожесть одного фрагмента после изменения громкости ~1,000,
  другой фразы того же C2-говорящего 0,845,
  другой C2-говорящий 0,250, голоса из другого источника 0,140–0,266.
  Это **не** независимая разметка личности.

Все эти WAV с длинной цифровой паузой или без ручной разметки:
полученные RTF и соответствия нельзя интерпретировать как
метрики непрерывного 20-минутного разговора или DER/cpWER.
Санитизированная выжимка без речи и персональных данных:
docs/evidence/speakerbook-titanet-honor-20261111.json.

**Контроль нагрева:** 20-минутная непрерывная QA-запись была
запущена на HONOR, но испытание остановлено нами через ADB при
показании датчика аккумулятора 47 °C. Результата длинной
обработки нет. Инструментальный runner сообщил Process crashed
из-за принудительной остановки — это **не** установленная ошибка
приложения. evidence/speakerbook-titanet-thermal-abort-20261111.json.
Повторять длительную нагрузку без температурного отсечения нельзя.

**Статус: черновик.** Нужны 20+ минут непрерывной речи, независимый
holdout с настоящими метками людей, оценка false-merge/false-reject,
DER/cpWER и проверка потребления памяти. Нельзя автоматически мержить
в main по одному успешному контрольному набору.

## Архитектура первоначального варианта C2 (история; не используется в текущем QA-пути)

Обычный длинный путь распознаёт файл пятиминутными блоками.
C2 выдаёт локальные слоты говорящих, которые нельзя просто считать
одними и теми же людьми в другом блоке.

За флагом globalSpeakerBook добавлено:
1. Nemotron C2 собирает собственные 512-мерные энкодерные представления
   на интервалах в 80 мс. Новых моделей или облачного API нет.
2. Немотрон профилирует только полные кадры с единственным активным
   голосом; частично занятые и перекрывающиеся кадры исключаются.
3. GlobalSpeakerBook сравнивает нормализованные векторы только с
   предшествующими блоками, косинус >=0,84 и преимущество над вторым
   вариантом >=0,07. Для связи нужно >=2400 мс чистой речи.
4. Два локальных голоса одного блока не могут сопоставиться одному
   глобальному ID. При недостатке/неоднозначности признаков остаётся
   старый безопасный локальный ID Block N / Speaker K.
5. IPC ограничен максимум восемью профилями по 512 элементов; результаты
   валидируются, а оригинальный текст ASR и время не изменяются.
6. QA-приложение имеет отдельный суффикс package .speakerbookqa
   и не перезаписывает установленную конкурсную сборку.

QA-порог для включения настоящего recognizeLong — >5 минут, чтобы
один и тот же метод можно было проверять на HONOR без тяжёлого
20-минутного файла. В обычной сборке порог остаётся >20 минут.

Для QA: -PnemotronProduct=true -PasrA3=true -PglobalSpeakerBook=true
По умолчанию флаг отсутствует и функциональность выключена.

**Ограничение:** векторы Nemotron — не специально обученная
модель идентификации личности говорящего. Косинус не равен вероятности.
Пороговые значения НЕ прошли независимую акустическую проверку;
выполнение unit-тестов не доказывает точность на настоящем аудио.

## Честное сравнение с Mugsize / Сквор

В tools/compare_transcript_outputs.py подготовлен воспроизводимый
WER/cpWER с оптимальным сопоставлением говорящих. Требуются:
одна ручная эталонная транскрипция, два результата *одного аудиофайла*
и одно устройство для измерения RTF.

Команда:
python tools/compare_transcript_outputs.py --reference reference.json --ours ours.json --theirs skvor.json --duration-s 180 --ours-wall-s 90 --theirs-wall-s 88

Тест:
python -m unittest discover -s tools -p test_compare_transcript_outputs.py -v

Скрипт не считает DER. Обязательно отдельно считать DER по общей RTTM
с collar 0 и 250 мс и согласованной политикой перекрытий.
Не сравнивать численные DER/WER из разных публичных наборов или устройств.

  instrumentation-тест CrossWindowSpeakerBookDeviceTest.
- Образец для контроля переноса ID: 68,45 с разрешённой тестовой речи
  с двумя голосами, цифровая пауза и повтор с коэффициентом 0,94.
  Общая длина 370,453 с. Содержимое не публиковалось в Git.
- Android-тест: PASS, 1/1, время самого распознавания 102,800 с,
  RTF по полной длине файла 0,2775.
- В обоих блоках получены голосовые профили; две глобальные группы,
  без изменения ID между повторами. Сохранено 8 фрагментов,
  включая 2 фрагмента перекрытия с неопределённым ID.
- Сравнение текста двух повторов (первый как условный образец) дало
  2 расхождения на 141 слово, приблизительно 1,42%.
  Это **не** WER к ручной транскрипции.
- **Важное ограничение:** длинная пауза пропускается с trimming
  нулевого цифрового сигнала, поэтому RTF 0,2775 нельзя переносить
  на шестиминутный непрерывный разговор.
- Для запуска прогона 6 минут QA-порог входа в тот же метод
  recognizeLong понижен до >5 мин; обычный продукт сохраняет >20 мин.
- При проверке обнаружено ложное предупреждение о нераспознанных
  говорящих после успешной длинной обработки. Исправлено; повторный
  аппаратный тест PASS 1/1 за 102,439 с (102,8 с внутри pipeline в
  первом прогоне и 101,812 с во втором).
- Два запуска дали полностью совпадающие восемь фрагментов:
  текст, speaker ID, интервалы и перекрытия. Предупреждение исчезло,
  а при полном отсутствии признаков говорящих останется обоснованным.
- Санитизированная JSON-выжимка фактов без аудио, серийного номера
  устройства и текста стенограммы: evidence/speakerbook-honor-smoke-20261111.json.

Аппаратный тест подтверждает работоспособность механизма на одной
записи с повтором, а **не** качество на новых независимых голосах,
внешнем шуме или перекрывающихся собеседниках. До внедрения в
основную сборку нужна слепая акустическая проверка cpWER / DER.

## Негативный контроль на разных исходных записях

- Два разных исходных тестовых клипа: 01_ru_two_speakers_slow.wav
  (2 голоса) и 05_ru_truecrime_three_speakers_natural.wav (3 голоса).
  Второй начинается на 302-й секунде; 421,3 с всего.
- Физический HONOR: 135,264 с обработки, RTF 0,321 на
  файле с длинной цифровой паузой; 21 сегмент, 2 обработанных блока.
- Из первой записи получены Speaker 1 и Speaker 2. Во второй
  получены Speaker 3, Speaker 4 и Speaker 2.
  Следовательно, текущий C2-embedding алгоритм склеил часть
  второго источника с голосовой группой первого.
- Негативный Android-test FAIL (1/1): условие отсутствия
  пересекающихся голосовых ID между двумя разными источниками нарушено.
- Авторы записей не имеют отдельной ручной разметки реальных
  идентичностей людей. Строго доказать ошибку личности по этим
  материалам нельзя, но результат означает серьёзный риск
  ложного объединения и блокирует включение экспериментального
  механизма по умолчанию.
- Полные WAV и транскрипции остаются локальными. Обезличенное
  свидетельство: evidence/speakerbook-honor-negative-20261111.json.

Вывод: успешный тест с повтором одной и той же речи недостаточен;
нужен отдельный, проверенный на независимых голосах энкодер
верификации говорящего (например, TitaNet), с отклонением
неоднозначных сопоставлений. Изменять cosine-порог только под
эти два клипа нельзя: это переобучение на контрольном примере.

## Допуск к продукту

Нужны реальный ARM64-тест со стабильными 512-мерными признаками,
пять минут + пять минут того же голоса на других слотах,
2–8 говорящих, новые голоса и помехи, стресс длинных файлов,
полный RTF, пиковая память, DER и cpWER на заранее отложенном
корпусе, и контроль отсутствия регрессий старой модели.
До этого релизный режим оставлять выключенным.
