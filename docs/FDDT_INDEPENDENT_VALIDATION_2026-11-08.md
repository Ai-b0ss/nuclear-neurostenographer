# Независимая проверка FDDT на HONOR — 08.11.2026

## Цель и метод

Тестирование на настоящем HONOR 10X Lite, Android 10, ARM64, авиарежим.
Приложение отдельного пакета ru.neurostenographer.app.fddtqa.
Не менялись основной APK 0.3.16 и логика работы Рузанны.

Одна и та же запись сначала обрабатывалась Nemotron C2 и GigaAM A3.
Затем поверх этих же слов и ходов говорящих выполнялся FDDT;
этот порядок исключает вариацию C2/A3 между сравниваемыми вариантами.
Результаты сохранялись в JSON посредством отдельного Android
инструментального теста, без сети и сервера.

## Более тихие участники

Корпус ivkond содержит заранее заданные множители громкости.
Ниже ошибка после оптимального назначения идентификаторов говорящих
именно более тихому из двух. Это оценка по словам, не DER.

| Запись | Тихий ID | Относительный уровень | Ошибки A3 | Ошибки FDDT |
|---|---|---:|---:|---:|
| ivkond_08.wav | 2 | 0.75 | 17 | 16 |
| ivkond_34.wav | 2 | 0.78 | 12 | 12 |
| ivkond_38.wav | 1 | 0.83 | 19 | 23 |
| ivkond_44.wav | 2 | 1.06 | 17 | 23 |
| ivkond_66.wav | 1 | 0.84 | 19 | 15 |

По тихой речи: улучшено 2 случая, не изменён 1, ухудшено 2
(ivkond_38 и ivkond_44). Поэтому нельзя делать вывод о полной
надёжности для тихих говорящих только по общему снижению ошибки.

## Алгоритм расчёта

Слова нормализуются с помощью Unicode NFKC, нижнего регистра,
замены ё→е и удаления пунктуации. Фразы конкатенируются по времени
в потоки каждого говорящего. С помощью DP выбирается оптимальное
однозначное сопоставление потоков эталона и предсказания, затем
вычисляется суммарный Levenshtein / количество эталонных слов.
Поток speaker_id=null считается отдельным unknown и штрафуется,
лишние говорящие дают ошибки вставок. Это вариант
permutation-invariant concatenated WER, но не официальный meeteval cpWER.

## Ограничения и инженерные решения

- Все 15 запланированных тестов Android завершились успешно; ещё
  2 дополнительных теста настоящего телефонного звука также прошли.
- В одном случае синтетики 4 говорящих без перекрытий FDDT не запускался
  и результат совпал с исходным; это правильная негативная проверка.
- В живом DataHive ru_000013 три ложных перекрытия FDDT откатил,
  ничего не изменив в стенограмме, но потратил ~21,9 с.
- В сложной синтетике дополнительный FDDT занимал ~36–63 с.
  При таких задержках включать его по умолчанию для часового
  аудио без дальнейшей оптимизации нежелательно.
- Измерение RAM на устройстве в одном моменте:
  PSS ~727302 KiB, Native Heap ~639124 KiB; это не пиковое
  потребление и не гарантия многочасовой записи.
- Разница средних ошибок по этим выборкам не является доказательством
  качества на всех естественных разговорах. Модель всё ещё может
  галлюцинировать или терять отдельную тихую речь.
- Экспериментальная ветка остаётся Draft PR #46. Стабильный
  конкурсный релиз v0.3.16-contest не менялся.
- Простой способ ускорения по минимальной длительности перекрытия
  не внедрён: он может пропустить подлинные короткие перебивания.

## Воспроизводимость и источники

Источник синтетики:
https://huggingface.co/datasets/ivkond/synthetic-speech-diarization-ru

Источник реальных разговоров (указать DataHive, CC BY 4.0):

Публичные фрагменты телефонной речи Nexdata-AI:
https://github.com/Nexdata-AI/93-Hours-Russian-Conversational-Speech-Data-by-Telephone

В GitHub должны попасть только обвязка теста, формула метрики и этот
сводный отчёт. Все чужие WAV/MP3, тексты стенограмм и приватные
результаты тестов сохраняются только на рабочем ПК в папке:
K:/nn-fddt-hybrid-20261108/.local/field_eval_20261108.

Для повторного расчёта (Python 3.10+ без сторонних библиотек):
python tools/evaluate_fddt_field_results.py --self-test
python tools/evaluate_fddt_field_results.py --data-dir <папка с manifest и results>

Обвязка Android:
app/src/androidTest/java/ru/neurostenographer/app/FieldEvaluationDeviceTest.kt
Запускается отдельным test APK с параметрами evalFile и evalMode.
