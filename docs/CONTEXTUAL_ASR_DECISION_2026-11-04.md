# R&D: контекстные термины, LM rescoring и осторожная офлайн-коррекция ASR

**Дата:** 04.11.2026. **Статус:** decision / experiment design; **все новые B-эксперименты NOT_RUN**. Только документация в независимом PR; нет изменения конкурсной сборки, моделей, Sonnet, HONOR, `main`. Проверить после завершения Sonnet своих работ и планируемого сравнения GigaAM.

## 0. Восстановленный замысел

Пользователь хочет, чтобы произнесённое «sherpa», «sherpa-onnx», «Nemotron», «GigaAM», «Kotlin», «МИФИ» не распадалось на похожие русские слова или неправильную транслитерацию, а текст оставался точным даже при профессиональной тематике. В исходном [DECISION_REGISTER R-08](DECISION_REGISTER.md) это уже записано как **B — необязательная проверка/исправление сомнительных фрагментов**, но **не реализовано**. [PROJECT_CHARTER](PROJECT_CHARTER.md) выделяет CORE/A/C/B и требует сохранять несогласия и исходные данные. Эта работа *не* изобретение нового основного модуля.

**Принцип:** улучшать точность и написание, не изменять смысл/говорящих/времена и не сочинять информацию по вероятной теме встречи. GigaAM v3 CTC INT8 + Nemotron C2 остаётся рабочим A0/C2 baseline. В коротких курируемых примерах WER 2–10%, но сложный независимый набор имел существенно больше ошибок; нельзя называть текущую задачу «исправить оставшийся 1%» без настоящей независимой проверки.

## 1. Пять разных механизмов, не смешивать

| Механизм | Где | Может помочь | Не может / ограничения |
|---|---|---|---|
| **B0. Детерминированный терминологический словарь / homophone replacement** | После ASR, до отображения/экспорта | `шерпа он икс` → `sherpa-onnx` при проверенном совпадении, регистр и формат техтерминов | Не восстановит исчезнувшее слово и не определит истину по одному контексту; «шерпа» может означать человека в горах |
| **B1. Decoder contextual biasing (hotwords)** | *Внутри* ASR | Повысить вероятность известных профессиональных слов во время поиска гипотез | Не является словарём замены; может вставлять термины, которых человек не произносил. В sherpa-onnx штатный hotwords только для Transducer + `modified_beam_search`, не CTC `greedy_search` |
| **B2. LM shallow fusion / N-best rescoring** | В процессе декодирования / выборе гипотез | Предпочесть сочетания слов по языковому контексту **с сохранением акустических свидетельств** | N-best/score должны реально предоставляться runtime; 1-best без аудио не позволяет восстановить потерянные акустические варианты. Различать beam search и внешнюю LM |
| **B3. Повторное ASR фрагмента** | Второй проход на оригинальном звуке | Использовать улучшенную A1..A4 e2e/RNNT на спорном интервале с перекрытием окон, перепроверить вставки/удаления | Подорожание по CPU/батарее; нужен контроль тишины, границ, alignment и возврата к raw |
| **B4. Маленькая локальная текстовая LM / корректор** | После ASR | Пунктуация, регистр, правописание терминов, подсказка исправлений с узким контекстом | Без аудио модель может *правдоподобно выдумать* слова/числа/отрицания. Текстовый LLM — только кандидат для предложений, а не источник истины |

**Важно про RNNT:** набор конфигураций, например `hotwords-file`, `hotwords-score` (типовой score 1.5), `max_active_paths` и `modified_beam_search`, **в sherpa-onnx относится к трансдьюсерным моделям**. Проверить совместимость конкретного GigaAM v3 RNNT / e2e RNNT и токенизации, pinned sherpa-onnx 1.12.20 и no-TTS Android runtime. Сам факт наличия RNNT ONNX не доказывает работоспособность modified beam, нужных токенов, native API или INT8 на Android. Обычный CTC `greedy_search` не получает hotwords от смены Kotlin-флага.

Также существует CTC+WFST/LM-декодирование в других runtime, но это **другая реализация и отдельная стоимость переноса**; не приписывать её существующему CTC APK.

### Детали из официальной документации

- sherpa-onnx hotwords: https://k2-fsa.github.io/sherpa/onnx/hotwords/index.html . Документация прямо требует transducer + modified beam; bias на уровне токенов. Для BPE могут потребоваться `modeling_unit=bpe`, `bpe_vocab`, соответствующие `tokens.txt`. Лексикон нужно тестировать на конкретном русско-английском коде.
- sherpa-onnx offline recognizer: https://github.com/k2-fsa/sherpa-onnx/blob/master/sherpa-onnx/python/sherpa_onnx/offline_recognizer.py . Поддерживает отдельные LM-конфигурации, `rule_fsts` / `rule_fars` для text normalization, homophone replacer. Наличие опций в *master* **не подтверждает** их в pinned 1.12.20 Android JNI.
- Paper: https://arxiv.org/abs/2409.09554 , *ASR Error Correction using Large Language Models*. Анализирует N-best и ограничения свободы генерации; не является оценкой конкретной нашей модели.
- Qwen3-0.6B (https://huggingface.co/Qwen/Qwen3-0.6B) — компактный **кандидат текстовой LM**, а не ASR, не подтверждён на HONOR, поддерживает много языков. GGUF/int4 и Android inference сначала изучать на хосте. Его размер, RAM/KV cache, скорость, точность русских исправлений, лицензия конкретных quantisations пока NOT_RUN.
- GigaAM `v3_e2e_ctc` и `v3_e2e_rnnt` уже обучены возвращать регистр и пунктуацию; не сравнивать их с A0 по «красоте» текста, оценивая только WER без punctuation F1.

## 2. Пример из реальной задачи: «шерпа»

Оригинальный произнесённый смысл зависит от звука и контекста:

| Контекст | Raw ASR (иллюстрация, не результат модели) | Безопасный вариант |
|---|---|---|
| Техническая встреча про Android ML, участники заранее указали термин | «мы используем шерпа он икс» | Предложить `sherpa-onnx`, показать raw и дать прослушать источник |
| Доклад о Гималаях | «нам помогал шерпа» | **Сохранить «шерпа»**, не подменять названием библиотеки |
| Просят «передай текст шерпе» | «шерпе» | Не заменять только потому, что `sherpa-onnx` есть в словаре |
| Разговор про `Nemotron`, но часть слова не слышна | «...» или сомнительное место | Не вставлять название модели из темы без акустического подтверждения |
| «мы не используем GigaAM» | «мы используем GigaAM» | Ни словарь, ни LM не имеют права угадывать пропущенное **«не»** по теме |

Проектные термины имеют **две независимые формы**: (a) произносимые варианты/похожие ASR-фразы и (b) каноническое написание в выходе. Например, `sherpa-onnx`: «шерпа он икс», «шэрпа онн икс», «шерпа оннх» — *гипотезы для словаря, не подтверждённый универсальный список фонем*. Не делать автоматической, необратимой замены всех «шерпа» в тексте.

### Словарь контекста (предлагаемая сущность)

Пользователь задаёт тему встречи и термин:
- `canonical`: `sherpa-onnx`;
- `spoken_variants`: перечень проверенных произношений (не выводить их из английского написания автоматически);
- `asr_surface_variants`: зарегистрированные варианты ошибок raw ASR;
- `type`: технология / человек / организация / сокращение, область применения;
- `is_domain_scoped`: да, чтобы не менять обычную речь;
- `mode`: предложить / автоматически применять **только после отдельного согласия на этот термин**, с записью до/после.

Исходный и исправленный текст + нормализация на экспорт сохраняются раздельно. Словарь нельзя использовать для подтверждения несуществующего произнесённого слова.

## 3. Два независимых пути: «лучше слышать» и «лучше писать»

1. **A-first (сначала Sonnet)**: проверить A0 `v3_ctc` против `v3_rnnt`, `v3_e2e_ctc`, `v3_e2e_rnnt`, `multilingual_ctc` 220M на неизменном DEV/HOLDOUT, SHA-256, унифицированных окнах; MOSS как независимая A+C гипотеза. Измерить вставки на границах окон отдельно. [План исследования](ASR_MODEL_HANDOFF_2026-11-04.md).
2. **B-first (исследование без Android-кода сейчас)**: подготовить словарь, антипримеры, правила допустимых исправлений и план сравнения. **Ни одну модель не загружать во время очистки компьютера Claude.**
3. **После измерений A:** если e2e уже решает пунктуацию, не добавлять лишний «пунктуатор». Если RNNT поддерживает hotwords — сравнить A1 без/с bias на том же аудио. Если A0 остаётся сильнее по WER, пробовать B0 поверх A0.
4. **Tiny LM gate:** только если B0 и A1 hotwords недостаточны на настоящем holdout и устройство имеет RAM/тепловой бюджет. Модель не получает права тихо переписывать реплики. Сначала PC dry-run, затем отдельный Android эксперимент.
5. **Пользовательская польза:** наряду с WER измерить время ручного исправления текста и число неверных автоматических правок. Для слова «шерпа» опаснее ложная замена, чем сохранение русской записи.

## 4. Воспроизводимый дизайн измерений

Те же неизменные WAV (hash+лицензия+reference) для всех сравниваемых вариантов. **Две группы:**
- DEV для выбора силы bias и правил нормализации; можно использовать искусственно составленные технические реплики, чистую/шумную речь, повторы A–B–A, разговорные формы.
- Слепой HOLDOUT **натуральных** русских бесед разных говорящих/микрофонов, с ручной дословной разметкой. Не тюнить на нём ни модель, ни словарь. Не подменять TTS независимой живой записью.

Сценарии: спецтермины (правильно и ошибочно услышанные), омонимы «шерпа», редкие имена/англицизмы, нарочито ложная подсказка, короткие отрицания `не`, числа/даты, вставки из окон, тишина/музыка, 2–4 голоса, overlap и шум, длинное аудио. Заранее отметить в эталоне, какой термин действительно произнесён, а какой нет.

**Варианты ablation:**
- A0 raw current CTC+greedy;
- A0 + B0 display-normalization, только заявленные словари;
- A1 RNNT greedy (если реально запускается);
- A1 RNNT modified beam, **без** hotwords;
- A1 RNNT modified beam **с** hotwords, несколько bias strengths (подбор только на DEV);
- лучшие e2e и multilingual **без** B, чтобы увидеть исходное преимущество;
- selected ASR + B3 второй проход спорных фрагментов;
- selected ASR + B4 tiny LLM c ограниченными edits **если** предыдущие gate успешны.

Если отсутствует N-best в runtime, отмечать `NOT_RUN` для rescoring, не имитировать варианты синонимами, сгенерированными LLM.

**Метрики:** raw и corrected WER/CER, доли S/D/I, **TER** (term error rate с объявленным знаменателем), precision/recall по редким терминам, **false term injection rate** на отрицательных примерах, количество изменений обычных слов, negation/number preservation, punctuation/casing F1 отдельно, cpWER при фиксированной C2 и корректной speaker reference. Отдельно **real wall RTF / RSS/PSS / батарея / температура** дополнительного B на ARM64. Статусы PASS/FAIL/NOT_RUN, confidence лишь если реально выдается и калиброван.

**Продуктовый критерий GO:** измеримый выигрыш на HOLDOUT при отсутствии статистически заметной деградации обычных слов и критических категорий (отрицания, числа, имена говорящих); не хуже по надёжности, работает без сети, не превышает согласованный CPU/RAM/thermal budget. **Без таких доказательств — предложения исправлений пользователю, не автоправка.**

## 5. Возможные выводы исследования (пока не результаты)

| Ситуация | Решение по умолчанию |
|---|---|
| e2e-модель снижает WER и хорошо ставит пунктуацию | Не добавлять LLM-пунктуатор без отдельного выигрыша |
| RNNT + hotwords снижает ошибки терминов, не вставляя лишнее | Рассмотреть настройку области/терминов на уровне ASR |
| CTC лучше RNNT в независимых метриках | Оставить CTC, сделать обратимый B0 словарь и UI review |
| LLM улучшает читабельность, но WER и factual consistency хуже | Разрешать только пользовательский режим «читабельный пересказ» с raw рядом, не изменять стенограмму |
| На HONOR B добавляет перегрев, OOM либо чрезмерный RTF | Не включать в обязательный пайплайн, применять вручную или отложить |

## 6. Интерфейс и доверие

В настройках профиля встречи — один понятный переключатель «Учитывать термины» и редактируемый список. В результате рядом с исправленным словом: «было: шерпа он икс → предлагается: sherpa-onnx», кнопки «Прослушать», «Принять», «Оставить». Не скрывать source audio и raw ASR. Режим «Дословно» по умолчанию; «Читабельно» отдельно. Пользовательская ручная коррекция имеет приоритет над автоматической.

## 7. Что передать Sonnet после её текущей задачи

Не сейчас. Когда Claude закончит очистку памяти и начнёт исследовательскую работу:
- сначала закрыть оговорённое сравнение **четырёх** дополнительных GigaAM и MOSS, не смешивая с B;
- затем отдельно проверить RNNT API `modified_beam_search`+hotwords на точном pinned runtime и русской токенизации, а также baseline punctuation in e2e;
- принести N-best/lattice/decoder confidence **только если реальные API их предоставляют**;
- выполнить ограниченное ablation на DEV и одном незатронутом HOLDOUT; не отправлять аудио в сеть и не коммитить исходные разговоры;
- отдельный R&D PR без замены конкурсного APK.

**Итоговый статус:** decision spec / NOT_RUN, без обещания прироста «последнего процента WER». Этот PR не содержит кода и не изменяет работу Claude.
