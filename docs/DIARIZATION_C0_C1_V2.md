# C0 против Nemotron на ПК: версия 2 доказательств

**Дата:** 3 ноября 2026. Заменяет выводы [версии 1](DIARIZATION_C0_C1.md) только там, где указано ниже. Отчёты версии 1 в [evidence/diarization-c0-c1](evidence/diarization-c0-c1) не менялись. Они воспроизводятся на коммите `56337be`, новые данные лежат в [evidence/diarization-c0-c1-v2](evidence/diarization-c0-c1-v2).

**Физический ARM64: NOT_RUN.** Все цифры здесь сняты на ПК.

## Что исправлено

| Проблема версии 1 | Как теперь |
|---|---|
| `comparison-ivkond.json` выдавал недостоверный DER как `SCORED` | `build_corpus.py` проверяет разметку по энергии кадров и не передаёт отвергнутые интервалы в эталон. Все 15 файлов ivkond дают DER `NOT_SCORED`, причина записана в `corpus-manifest.json`. Проверка эвристическая: покрытие от 96% при доле кадров без энергии выше 33% |
| Упавший запуск исчезал из оценки | Сбой или таймаут оценивается как пустая гипотеза: 100% DER, все слова удалены, файл остаётся в знаменателе и в счётчике сбоев. Негативные тесты в `test_score_bench.py` |
| Разные границы времени у C0 и C1/C2 | Единые поля: `load_ms`, затем `infer_ms` до записанного файла интервалов, включая постобработку; отдельно `read_ms` и `wall_ms` |
| Результаты могли устареть незаметно | У запуска есть отпечаток модели, кода, порога, рантайма и аудио. При расхождении запуск выполняется заново. `score_bench.py` отказывается считать, если файл интервалов, аудио или эталон не совпадает с записью. Отпечаток пути сравнения кода Python учитывает `run_c1.py`, `diarize.py` и версию ORT |

На результат DER исправления не повлияли: основные значения совпали с версией 1. Сбоев в прогоне нет, поэтому правило пустой гипотезы проверено тестами, а не реальным падением. CI bootstrap немного изменился из-за порядка записей.

## Ручная разметка DataHive

**`NOT_SCORED`: человек эталоны не проверял.** Я не могу прослушивать аудио, поэтому DER по ручной разметке не посчитан.

Готов инструмент: `tools/diar_bench/manual_review.py prepare` создаёт стерео-WAV и метки Audacity для 6 заранее выбранных звонков, включая `ru_000001`. `score` считает DER только по полностью размеченным файлам и пишет результат отдельно от VAD. Аудио и метки остаются на машине проверяющего. Пока результат: [manual-review.json](evidence/diarization-c0-c1-v2/manual-review.json), 0 файлов из 6.

Автоматический разбор по интервалам ([explain-recordings.json](evidence/diarization-c0-c1-v2/explain-recordings.json)) для `ru_000001`: C2 разбивает речь принимающего на два кластера и смешивает с ними речь звонящего. Это не человеческий эталон и причину не объясняет.

Команды версии 1 остаются, по умолчанию результаты пишутся в `ROOT/results-v2`. Новые проверки:

```bash
python -m unittest tools/diar_bench/test_score_bench.py
```

```bash
python tools/diar_bench/make_comparison.py --root ROOT --evidence docs/evidence/diarization-c0-c1-v2 --code-commit COMMIT
```

Запускайте тесты из `tools/diar_bench`, если модульные пути не разрешаются.
