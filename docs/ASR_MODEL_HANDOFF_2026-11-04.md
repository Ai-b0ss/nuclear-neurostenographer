# Задание действующей сессии Sonnet — ASR-кандидаты и joint A+C

Дата 04.11.2026. Этот документ — поручение для Claude Code Sonnet, НЕ отчёт о выполненной работе. Реализацию и тесты в текущей интеграционной ветке не менять. Начать только после завершения Git/PR-консолидации.

## Охват и порядок

Baseline A0: `GigaAM v3 CTC INT8` (уже работает в подписанном Android RC1).

**Четыре дополнительных ASR-кандидата** из официального https://github.com/salute-developers/GigaAM :
1. `v3_rnnt`
2. `v3_e2e_ctc`
3. `v3_e2e_rnnt`
4. `multilingual_ctc` на основе 220M-энкодера (не `multilingual_large_ctc` 600M).

**Отдельная совместная A+C архитектура:** `MOSS-Transcribe-Diarize 0.9B` — https://github.com/OpenMOSS/MOSS-Transcribe-Diarize . Она в одном проходе выводит слова, speaker IDs и интервалы. `VibeVoice-ASR/Streaming` — независимый вторичный вариант для исследования при наличии ресурсов: https://github.com/microsoft/VibeVoice . Не путать MOSS, VibeVoice, GigaAM RNNT и Nemotron C2.

## Инженерные требования

- Продолжить существующую сессию Sonnet и использовать отдельную R&D ветку / worktree от актуального `main` или `integration/c2-honor-20261104`, не править, не устанавливать и не ломать конкурсный RC1, Sonnet/Opus-ветки, CI и HONOR.
- Сначала проинвентаризировать свободное место, Python/venv, модели и runtime. Предыдущие замеры: C: ~1.19 GiB, K: ~2.61 GiB свободно. Не ставить PyTorch и не скачивать все модели одновременно на почти заполненный диск. Если пространства не хватает — изучить безопасные возможности, а не трогать чужие данные/сборки. Работать последовательно, очищая только собственные временные файлы.
- Проверить точные upstream ревизии, лицензии и checksum весов; документировать параметры декодирования, sample rate и число потоков, размер и память; без платных API.
- Единый неизменный manifest WAV+SHA и reference по двум группам: DEV для отладки, HOLDOUT независимые естественные русские диалоги 2–4 людей для финального качества. Не выдавать TTS, раздельно склеенные актёрские реплики или автоматически псевдоразмеченные звонки за независимую ручную разметку.
- Для всех A0+A1..A4: WER, CER, ошибки вставок/пропусков/замен, качество пунктуации и нормализации отдельно, hallucinations на тишине/музыке, 20-минутная устойчивость и PC RTF/RSS. Базовую A0 повторить на тех же WAV и с теми же ASR окнами (20-секундный QuietCuts), иначе не делать прямых заявлений об улучшении самой модели.
- С C2 фиксированными turns сравнить cpWER без молчаливого удаления неизвестных говорящих, DER не приписывать одиночной ASR-модели. Оценить повторения на границах ASR окон и источник проблем (границы, модель, декодер), не лечить слепым дедупом.
- MOSS отдельно сравнить с A0+C2 на идентичном WAV, тексте, говорящих и таймкодах; фиксировать ошибки speaker recurrence A–B–A, overlap, ложные слова; WER, строгую cpWER, DER только при действительно пригодной ручной разметке. Порт на HONOR обсуждать только после реального выигрыша на ПК и оценки RAM/RTF/ONNX compatibility.
- Сохранять per-file JSON/CSV, агрегаты, версии, SHA и PASS/FAIL/NOT_RUN, не публиковать private audio. При падении учитывать FAIL; не выбрасывать сложные записи из агрегатов. Не тюнить по HOLDOUT.
- Не запускать одновременно несколько тяжёлых моделей на RTX 2060 Super и не перегревать HONOR. Обновлять план после каждого завершённого кандидата, а не одной пачкой в конце.
- Критерий внедрения: достоверное улучшение независимых ошибок при приемлемых ARM64 ресурсах. Не заменять baseline из-за красивой пунктуации без WER/cpWER evidence.

3. Причины FAIL/NOT_RUN, предложения GO/NO-GO на Android и влияние на главную конкурсную сборку.
4. Независимый исследовательский PR/документация, без автоматического merge в `main`.
5. Короткое сообщение владельцу только по результатам, без периодических сообщений каждые несколько секунд.
