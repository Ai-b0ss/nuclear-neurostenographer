# ETA для коротких записей — диагноз и приёмка, 08.11.2026

## Почему не показывался

ETA **не исчез при слиянии веток**. Коммит `d35d6c4` с `AudioProcessingClock.kt` уже включён в `main` через PR #44. Однако `TranscriptionViewModel.recognizeLong()` создавал эту оценку **исключительно для аудио более 20 минут**. Для обычных записей `recognizeBlock()` показывал шаги обработки и прогресс окон, но не числовое оставшееся время. Значит, проблема заключалась в условиях использования модуля, а не в пропавшем коммите.

## Исправление

Добавлен отдельный класс `ShortProcessingEta` для обычных файлов; прежняя логика длинных аудио не меняется. Новый прогноз берёт время из монотонных часов `SystemClock.elapsedRealtime` и измеряет завершённые этапы: Nemotron C2, распознавание A3/Whisper и необязательный FDDT. До первого измерения отображается «Уточняю оставшееся время…». При просроченном прогнозе и неопределённой дополнительной обработке оценка временно исчезает, вместо ложного «00:00». Доли этапов приблизительные — это не точные проценты распознанных слов.
