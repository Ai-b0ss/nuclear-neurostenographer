# Слова по говорящим по меткам времени ASR (0.3.2-contest, 05.11.2026)

## Проблема
Микрофонная запись диалога на 4 говорящих без пауз (hold-s4-r30, HONOR, 0.3.1): WER 20/61, cpWER-U 31/61 против 16/61 и 23/61
при прямой обработке файла. Эхо комнаты накладывает хвост реплики на начало следующей, C2 отмечает перекрытие на каждой
смене говорящего, а `OfflineAsr` резал окна ASR по каждой границе тёрнов: начала реплик отрывались и обрубались
(«открой температуру» → `Откройте.` + `Натура.`), появлялись ложные обрывки (`Так`, `Очень`, `Далист.`).

## Что изменено
1. **Окна ASR — по сплошной речи.** `DiarizationTimeline.speechWindows` объединяет все интервалы речи C2 (включая короткие и
   «неопределён»), если пауза между ними меньше 500 мс; режет только на паузах и по лимиту 20 с (точку сдвигает `QuietCuts.refine`).
   Смена говорящего окно больше не режет.
2. **Время слов — из ASR.** sherpa-onnx 1.12.20 для NeMo-трансдьюсера A3 отдаёт `OfflineRecognizerResult.timestamps`: по одной
   метке на токен, в **секундах от начала окна**, начало токена, шаг 40 мс (кадр энкодера GigaAM); `durations` пустой.
   Проверено на A3 (opset-fix) на ПК. `TokenWords.words` собирает из токенов слова (токен с пробелом открывает слово,
   пунктуация прилипает к слову и не растягивает его время); конец слова — начало следующего или +240 мс после последнего токена.
   Слова раскладываются по говорящим существующим `TranscriptFusion.attributeWords`: слово в перекрытии или рядом с
   неопределённым/коротким тёрном честно остаётся «Не определён» с пометкой перекрытия. Пунктуация A3 сохраняется.
   Запасной путь: окно без согласованных меток (и путь без диаризации, и CTC-сборка) — прежняя привязка фрагментов.
   `provenance.timestamp_source` = `asr_token_timestamps`.
3. Имя экспорта: «Запись 5 нояб., 01:40» больше не обрезается на точке — убирается только известное аудиорасширение.

Найдено и исправлено при проверке на телефоне: `DiarizationReply.validate` (проверка ответа изолированного воркера)
пересчитывала окна по старому правилу и отвергала новые — диаризация падала в «говорящие неизвестны». Теперь обе стороны
используют `DiarizationTimeline.speechWindowsOf`; ПК-харнесс этот путь не проходит, поэтому добавлен тест ядра.

Обычная (CTC) сборка меток времени не использует и режет окна по тёрнам, как раньше (`DiarizationTimeline.turnWindows`).

## Ограничения
- Микрофонный случай (эхо комнаты) на телефоне повторно не снят: аудио записей приложение не хранит. **Нужна новая запись
  владельцем** тем же способом (воспроизведение `mic-test-2-4speakers.wav` → «Записать» → «Распознать» → экспорт JSON).
- cpWER-U на hold-s4-r30 вырос (23 → 27): C2 сам отмечает перекрытие в начале почти каждой реплики, и слова там теперь
  честно «Не определён», а не приписаны соседнему говорящему. По 29 дорожкам cpWER-U не хуже (ДИ включает 0).
- Метки RNN-T — момент выдачи токена (шаг 40 мс), не акустическое выравнивание; конец слова оценён (+240 мс).
- Эталоны — синтетика TTS; естественной речи с ручной разметкой нет. По одному прогону.
