# Слайды организаторов Nuclear IT Hack («Нейростенографист», Hex.Team) — перепечатано с 20 картинок из ChatGPT-чата

Источник: слайды организаторов (презентация задачи 06.11.2026), переписанные с картинок. Организационные слайды (ИВТ 2.0, HEX.TEAM, картинки) не включены. Устные уточнения экспертов вынесены в конец.

## Формулировка задания
Разработайте Android-приложение, которое **локально** преобразует аудиозаписи разговоров в текст, автоматически определяя говорящих и разделяя их реплики.
Приложение должно формировать структурированную расшифровку диалога с указанием участников и временных меток. Результат должен быть доступен для просмотра в приложении и экспорта в файл. **Все этапы обработки должны выполняться непосредственно на Android-устройстве.**

## Обязательные требования
Команда должна разработать приложение, которое:
- работает под управлением Android OS;
- **использует локальную LLM**;
- импортирует аудиозаписи из памяти устройства;
- преобразует речь в текст;
- автоматически определяет и разделяет говорящих;
- формирует временные метки для реплик;
- отображает полученную расшифровку;
- экспортирует результат в файл.

## Ограничения обработки
Запрещается:
1. передавать аудиозаписи внешним сервисам для распознавания;
2. использовать облачные API для транскрибации, диаризации **или обработки текста**;
3. выполнять вычисления на удалённом сервере или компьютере;
4. подменять работу модели заранее подготовленной расшифровкой.

Приложение должно выполнять основную задачу без подключения к интернету. Все необходимые модели должны быть доступны на устройстве к моменту проверки. Использование готовых моделей и библиотек допускается.

## Ограничения участников
Мы понимаем, что современные решения без вклада ИИ невозможны. ИИ — это ваш инструмент. Важно всестороннее и глубокое понимание вашего решения, а не факт его наличия.
Участники самостоятельно определяют: модели распознавания речи, диаризации и LLM; архитектуру приложения; способы интеграции моделей с Android; алгоритмы предварительной и последующей обработки аудио; подход к определению границ реплик; внутренние форматы хранения данных; интерфейс пользователя; способы повышения производительности и точности.

## Ввод и вывод
Входные данные: аудиофайл, импортированный пользователем из локального хранилища Android-устройства, либо записанный из интерфейса приложения.
Выходные данные: структурированная расшифровка в формате JSON, содержащая текст каждой реплики, идентификатор говорящего, время начала и окончания реплики.

## Формат JSON-вывода
Структура и типы: `transcript` — array (массив реплик); `speaker_id` — string; `start_ms`, `end_ms` — integer (время в мс); `text` — string.
```json
{
  "transcript": [
    {
      "speaker_id": "speaker_1",
      "start_ms": 1250,
      "end_ms": 4380,
      "text": "Добрый день!"
    }
  ]
}
```

## Проверка решений
Работоспособность приложения проверяется экспертами на заранее подготовленных аудиозаписях. Порядок проверки: эксперты устанавливают предоставленный заранее APK; импортируют **три тестовые записи диалогов котиков**; запускают транскрибацию и диаризацию; экспортируют результаты обработки; сравнивают их с эталонными расшифровками; рассчитывают показатели точности (WER) и время обработки (RTF). Все команды проходят проверку на одинаковых тестовых данных.

## Примеры решений, в порядке улучшения результата
**Базовое:** работающий Android APK; импорт аудиофайла; использование локальной LLM; распознавание речи; автоматическая диаризация; временные метки реплик; отображение и экспорт результата.
**Средний уровень:** предварительная обработка аудиосигнала; фильтрация пауз и неречевых фрагментов; устойчивое определение участников при смене реплик; восстановление пунктуации; отображение прогресса обработки; воспроизведение аудио с переходом к соответствующей реплике.
**Ultra Pro Max:** обработка фонового шума и некачественных записей; распознавание коротких реплик и перебиваний; обработка одновременной речи нескольких участников; устойчивое распознавание при различиях в тембре и манере речи; оптимизация использования оперативной памяти; ускорение инференса за счёт аппаратных возможностей устройства; редактирование и повторная обработка отдельных фрагментов.

## Устные уточнения экспертов (по расшифровке записи выступления; точность дословной расшифровки не гарантируется)
- Точность распознавания важнее точности диаризации; скорость и точность важны оба (см. таблицу баллов).
- Тестовое устройство: стандартный Android-эмулятор, 4 ГБ ОЗУ, одинаковый для всех команд. Размер APK не учитывается.
- Текст должен быть максимально близок к сказанному: не приглаживать, не убирать паузы и междометия.
- Перекрытие голосов: в идеале разобрать обе реплики. Сохранение ID говорящих между сессиями — желательно (как в Google Диктофоне). Real-time — как опция. Summary через LLM — необязательный бонус.
- Язык: преимущественно русский. Шаблон репозитория — «очень серьёзная рекомендация».
- Слайд «использует локальную LLM» командой признан ошибочным и не реализуется.
