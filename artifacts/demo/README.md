# Демонстрация кейса Hex.Team — локальные проверенные материалы

## Итоговая видеодемонстрация с ETA

**Новый локальный APK-кандидат**, SHA-256 `60db53a52ae637eacc21cbff650560d719f5eae7e78fbb92bbf9aabc465ca4c1`, 636 818 690 байт, HONOR DNN-LX9 / Android 10 ARM64. Он не является опубликованным `v0.3.17-contest`.

- [Непрерывная запись экрана: ETA → 3 говорящих → проигрывание → сохранение JSON](ITAM-demo-3speakers-eta-playback.mp4), проверена полным декодированием FFmpeg.
- [Реальный входной WAV](ITAM-demo-3-speakers-33s.wav) (33,507 с, опубликованный синтетический корпус, 3 последовательных голоса).
- [Фактически экспортированный JSON](ITAM-demo-3-speakers-33s-export-eta.json): 7 реплик.
- [Протокол видеопроверки](video-verification-eta.json): PASS всех этапов, числовые ETA `00:16 → 00:17 → 00:04`, пользовательское время 33,84 с.

Видео — запись экрана **без системного аудио**; исходный звук находится в WAV. Если распространять демонстрацию внешне, необходимо приложить APK **с тем же SHA**, иначе видео не доказывает функции ранее опубликованного бинарника.

**Историческая демонстрация предыдущего локального кандидата с плеером.** Видеоматериал архивный, он не должен выдаваться за опубликованный APK 0.3.17. Актуальная демонстрация ETA + плеер и её APK теперь опубликованы в [финальном релизе](https://github.com/Ai-b0ss/nuclear-neurostenographer/releases/tag/v0.3.17-eta-playback-final).

## Новая демонстрация

- Видео: [ITAM-demo-3speakers-playback.mp4](ITAM-demo-3speakers-playback.mp4) — 1 минута 22 секунды, экран физического HONOR DNN-LX9 Android 10, запись scrcpy; без звука, так как захват системного аудио не поддерживается этим устройством. MP4 полностью декодирован FFmpeg без ошибок.
- Исходный аудиофайл: [ITAM-demo-3-speakers-33s.wav](ITAM-demo-3-speakers-33s.wav), 33,507 с, **три говорящих последовательно, синтетические TTS**. SHA-256 `7b5d5f9c8d5a984d193c2a0e31afe5dc6e3c1fb068d9499d552f104c0a6c4ce9`. Это проверенный пример из опубликованного корпуса ivkond/synthetic-speech-diarization-ru, а не запись с людьми и не скрытый тест жюри.
- Экспорт: [ITAM-demo-3-speakers-33s-export.json](ITAM-demo-3-speakers-33s-export.json), реально сохранён на HONOR и затем прочитан с устройства. Содержит ровно семь реплик.
- [Протокол проверки](video-verification.json): PASS импорта, выполнения ASR+диаризации, плеера с переходом к реплике и фактического сохранения JSON.

## Содержание видеозаписи

1. Открытие файла через Android OpenDocument.
2. Этапы распознавания на телефоне без сети и без готового текста.
3. Итоговая стенограмма: три говорящих, семь реплик, таймкоды и пунктуация.
4. Воспроизведение исходного WAV, перемотка к третьей реплике.
5. Нажатие «Сохранить JSON», системный диалог сохранения и возврат в стенограмму.

**Контроль кандидата:** SHA-256 APK `48569e1ddeb1f7b2903a2e7c0893a287b1edef5d4daf3e8d8c54b682c247da72`. Видео и WAV не заменяют проверку опубликованного релиза. Для строго исходного 0.3.17 без плеера есть предыдущая демонстрация в [GitHub Release](https://github.com/Ai-b0ss/nuclear-neurostenographer/releases/tag/v0.3.17-contest), но там не показан экспорт на видео.

В шаблоне другого кейса упоминалась передача данных динамик→микрофон. Для Hex.Team это **не требование**: демонстрируется офлайн-стенографирование, не акустическая передача файлов.

После получения разрешения на внешнюю публикацию обновлённое видео следует поставлять вместе с **соответствующим APK**. Отдельная загрузка нового видео к старому APK создала бы ложное представление о его возможностях.
