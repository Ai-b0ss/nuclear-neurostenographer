# Нейро-стенографист · Nuclear IT Hack 2026

**Замысел, ключевые решения и карта переписки GPT / Claude:** [база знаний проекта](docs/KNOWLEDGE_BASE.md). Это живая документация; факты о работоспособности проверяйте по [PROGRESS](docs/PROGRESS.md).

**Android-приложение для локальной расшифровки аудиозаписей с определением говорящих и временными метками.**

**Состояние: экспериментально, NOT_READY.** Порог кластеризации по умолчанию — 0.8. На составной русской актёрской пробе D/M/D различаются: WER и cpWER по 1/41 (2,44%); прежний 0.9 объединял голоса (cpWER 60,98%). Эта проба использована при выборе порога и не является независимой от настройки контрольной выборкой или оценкой корпуса. Отдельная контрольная актёрская проба из четырёх клипов того же датасета, запущенная только при 0.8: WER и cpWER по 2/92 (2,17%), M-D-M-D определены верно. Android x86_64 выполняет запись/импорт/экспорт; DER, физический ARM64, разговорная запись микрофона, качество перекрытий и условия публикации ещё не проверены полностью. [Доказательства и ограничения](docs/PROGRESS.md).

## Что реализовано
- Kotlin / Jetpack Compose, запрос разрешения микрофона, запись 16 кГц WAV, импорт аудиофайла.
- Kotlin-ядро сопоставляет текст с переданными модельными интервалами и сохраняет их метки/пересечения. Оно не исправляет ошибочные кластеры модели; неоднозначная атрибуция остаётся неизвестной.
- Экспорт TXT, JSON, SRT из реального ASR. Интервалы в миллисекундах обозначают входные фрагменты до 20 секунд, объединённые в реплики одного говорящего до 60 секунд; принудительный разрез сдвигается к ближайшей паузе, но слова на границах всё ещё могут обрезаться. Неоднозначная речь остаётся без говорящего. JSON сохраняет источник интервалов, длительность и предупреждения.
- Импорт PCM16 WAV проверяется до смены источника и сохраняется в локальную копию. Ошибка нового импорта сохраняет предыдущий результат. Импорт MP3/AAC/M4A/Vorbis/Opus/FLAC проверен на числовых аудиофикстурах Android x86_64/API 33. Доступность на других устройствах требует проверки. [Ограничения и тесты](docs/AUDIO_IMPORT.md).
- Облачная сборка APK и ручной запуск Android-эмулятора через вкладку **Actions**.
- Нет разрешения INTERNET в манифесте; аудиозаписи не передаются в облако.

## Как получить APK и установить на телефон
APK не публикуется (учебный проект). Его собирают сами: `python tools/build_local_apk.py`
(локальный JDK 17, Gradle 8.9 и SDK 35 лежат в `.local`, ничего ставить не нужно; сборка ≈2 минуты)
либо по запросу в GitHub Actions. Затем `python tools/offline_kit.py assemble --apk ...` собирает
комплект (APK + `gigaam-v3.zip` + `diarization.zip` с SHA-256), а `phone_kit.py install` по USB
ставит всё на телефон без выбора ZIP в интерфейсе. Нужны только Python и adb. Подробно:
[docs/OFFLINE_KIT.md](docs/OFFLINE_KIT.md), приёмка на телефоне: [docs/PHONE_ACCEPTANCE.md](docs/PHONE_ACCEPTANCE.md).
Старые artifacts main относятся к UI-базе.

**Старые APK на main содержат только исходную UI-демонстрацию.** Интеграция продолжается в `feature/long-recordings` (черновик PR #9), без слияния в main. Стандартная сборка теперь выбирает закреплённый runtime без TTS; полный GPL/TTS AAR доступен только как явная регрессия. JSON сохраняет хеш runtime, а CI сверяет упакованные JNI с AAR. Публикация нового APK пока отключена до завершения проверки notices и приёмки устройства; [подробности](docs/RUNTIME_LICENSES.md).

`python tools/provision_asr.py` использует проверенный локальный кеш или существующую авторизацию GitHub CLI для загрузки точного artifact сборки. Недоступность artifact завершает команду ошибкой, без возврата к GPL/TTS. Можно передать уже скачанный файл через `--runtime-file`; его SHA-256 всё равно проверяется.

## Метрики и память

`python tools/test_score_transcript.py` проверяет расчёт WER/cpWER/DER на авторских
текстовых тестах. [Формат и условия оценки](docs/BENCHMARKS.md) требуют независимой
разметки. У имеющегося русского WAV её нет: метрики остаются **NOT_SCORED**.
Отдельная [составная актёрская проба из трёх реплик](docs/RUSSIAN_EVALUATION.md)
имеет внешние текст/метки: при 0.8 WER/cpWER по 2,44%, A–B–A PASS; при
прежнем 0.9 cpWER 60,98%. Проба использована при выборе порога. DER не
считался без независимых речевых границ; качество реальных совещаний не доказано.
Импорт WAV теперь использует меньше памяти с точным совпадением PCM; измерения
Windows не подтверждают пиковую RAM или скорость смартфона. Облачный Android-тест
сохраняет JSON и снимки PSS даже при последующем сбое; это не пиковая RAM и не
измерение нагрева/энергии физического телефона.

## Следующий рубеж
Проще всего поставить модели комплектом (см. выше). Вручную: на ПК `python tools/provision_asr.py --model` (Python 3.11+), перенесите `.local/gigaam-v3.zip` на телефон и выберите «Установить модель ZIP». Нужны около 500 МБ свободного места. Модель проверяется по SHA-256. Затем запишите или импортируйте PCM16 WAV (1–2 канала, 8–48 кГц, 0,1 с–20 минут), нажмите «Распознать офлайн». Импорт файла ограничен размером около 230 МБ, а время декодирования сжатого аудио ограничено половиной длины файла (от 1 до 10 минут), поэтому очень длинный файл на медленном телефоне всё же может не импортироваться; доступность кодеков зависит от устройства, физический ARM64 ещё не проверен. Для сборки без модели: `python tools/provision_asr.py`, затем Gradle 8.9 / JDK 17 / SDK 35.

Для экспериментальной диаризации выполните `python tools/provision_diarization.py`, перенесите `.local/diarization.zip` и выберите «Установить модели говорящих ZIP». При недоступности диаризации распознавание продолжается с неизвестными говорящими и предупреждением. Дальше нужны Android inference на эмуляторе и физическом ARM64, исправление нативного overlap-сбоя и тесты WER/DER/cpWER на смартфоне. См. [Issues](https://github.com/Ai-b0ss/nuclear-neurostenographer/issues).

**Очистка:** кнопка «Удалить локальное аудио и результат» удаляет записи и временные аудиокопии приложения. Экспортированные документы удаляются отдельно. Это обычное удаление файлов, без гарантии физического стирания с флеш-памяти. Поставщик выбранного документа может самостоятельно использовать облако.

**Безопасность:** публичный репозиторий; не публиковать чужие разговоры, записи встреч, персональные данные, API-ключи или закрытые модельные веса.
