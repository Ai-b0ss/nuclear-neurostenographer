## Установка и использование

1. Скачайте [финальный APK](https://github.com/Ai-b0ss/nuclear-neurostenographer/releases/download/v0.3.17-eta-playback-final/Neurostenographer-0.3.17-playback-candidate.apk) (≈637 МБ; SHA-256: `60db53a52ae637eacc21cbff650560d719f5eae7e78fbb92bbf9aabc465ca4c1`).
2. На Android разрешите установку APK из выбранного источника и установите приложение. Все необходимые модели уже включены, отдельно скачивать их не требуется.
3. Откройте **«Нейростенограф»**. Нажмите **«Открыть аудиофайл»** и выберите запись либо **«Записать»** для записи с микрофона.
4. Дождитесь обработки на телефоне: приложение показывает этапы и ориентировочное оставшееся время. Интернет не нужен, можно включить авиарежим.
5. Откройте стенограмму, проверьте говорящих и таймкоды; нажмите ▶ возле реплики для прослушивания с её начала.
6. Нажмите **«Сохранить JSON»**, выберите папку и подтвердите сохранение. Выход соответствует конкурсному формату `transcript[]` с `speaker_id`, `start_ms`, `end_ms`, `text`.

**Проверенный телефон:** HONOR 10X Lite (DNN-LX9), Android 10 ARM64. Контрольный пример — [трёхголосый WAV](artifacts/demo/ITAM-demo-3-speakers-33s.wav) и [полученный JSON](artifacts/demo/ITAM-demo-3-speakers-33s-export-eta.json). Проигрыватель и ETA относятся к новой финальной сборке, не к предыдущему опубликованному APK 0.3.17. Оставшиеся ограничения и условия честно описаны выше.

## Что умеет

- **Импорт файла** (WAV/MP3/M4A/OGG/FLAC… — что декодирует телефон) или **запись с микрофона** → стенограмма с говорящими и временем реплик. Лимиты ввода — 8 часов / 5 ГБ; после 20 минут текст читается блоками без сквозных ID говорящих. Это не заявление о проверенном восьмичасовом разговоре.
- **Живая расшифровка** (кнопка «Живая расшифровка», с 0.3.8): текст появляется во время разговора, в среднем через ~1,4 с после конца фразы (HONOR). После «Стоп» говорящие пересчитываются тем же алгоритмом, что при импорте файла.
- **Перекрытия речи** (0.3.17): FDDT получает маску выбранного участника и помогает назначить автора сомнительным словам A3. Назначение допускается при однозначном совпадении слова и времени только у одного голоса. Сам текст, пунктуация и таймкоды A3 сохраняются; неоднозначные слова остаются `unknown`. После живой записи с перекрытиями доступна отдельная кнопка полного уточнения.
- **Индикатор микрофона**: спокойная полоса настоящего уровня звука в обычном и живом режимах. На тишине нет выдуманной активности. Таймер обычной записи сохраняет отсчёт при пересоздании экрана.
- **Экспорт TXT / SRT / JSON** с миллисекундами; имена говорящих можно задать вручную; поиск по стенограмме.
- **Словарь терминов** (B0, с 0.3.13 — около 360 терминов: кейс Hex.Team (ИБ, реверс, АСУ ТП, встраиваемые системы), корпоративный русский IT-сленг (дейли, планирование, ретро, инциденты), регуляторы и повестка российского IT (РКН, Минцифры, ФСТЭК, 152-ФЗ, КИИ, импортозамещение, российские продукты); [Hex.Team](docs/TERM_DICTIONARY_HEX_2026-11-07.md), [сленг и повестка РФ](docs/TERM_DICTIONARY_RU_IT_2026-11-07.md)): предлагает правильное написание терминов, применяется только с согласия пользователя, исходный текст распознавания сохраняется. Проверено: ПК — 0 ложных правок на 29 диалогах; телефон (HONOR, 07.11) — применение и откат в интерфейсе на синтетической записи, точность на живой речи не измерялась.

| Слова → говорящие | метки времени токенов A3 сопоставляются с репликами C2 (`TranscriptFusion`) | — |
| Уточнение перекрытий | GigaAM e2e RNN-T + 98 304 обученных параметра FDDT; адаптеры подготовила Рузанна. В продукте уточняет ID, сохраняя слова A3 | Веса базы GigaAM: MIT; происхождение адаптеров — переданный командой архив |
| Живой режим | Silero VAD → A3 по фразам, C2 в отдельном потоке, финализация после «Стоп» | MIT |

## Сборка

Модели и подписывающий ключ в Git не хранятся. Продуктовый APK собирается локально:

```bash
bash tools/build_product_apk.sh
```

Перед сборкой с FDDT подготовить закреплённые модели из архива команды:

```bash
python tools/prepare_fddt_assets.py --archive '/path/to/fddt_rnnt 2.zip'
```

Продуктовые флаги: `-PnemotronProduct=true -PasrA3=true -PenglishAuto=true -PfddtHybrid=true`.
Для отдельной проверочной установки добавить `-PfddtQa=true`. Полная замена слов FDDT включается отдельно через `-PfddtWordRecovery=true`; это другая политика, её cpWER нельзя выдавать за улучшение обычного WER продуктового режима.

Скрипт проверяет наличие закреплённых по SHA-256 файлов (`app/libs/sherpa-onnx-1.12.20.aar`, `.local/productAssets/gigaam-v3-e2e-rnnt.zip`, `.local/productAssets/nemotron.zip`, `.local/realtimeAssets/silero_vad.onnx`) и вызывает Gradle с флагами `-PnemotronProduct=true -PasrA3=true`. **Без `-PasrA3=true` APK не работает** (так были сломаны 0.3.4–0.3.6): перед публикацией проверяйте в сгенерированном `BuildConfig` `ASR_A3 = true` и `REALTIME = true`.

Юнит-тесты ядра (16 групп, JDK 17): `gradle :core:runCoreTests`. Проверки на телефоне — инструментальные тесты в отдельных пакетах `.realtime` и `.solhigh`, чтобы не трогать установленное приложение: [docs/PHONE_ACCEPTANCE.md](docs/PHONE_ACCEPTANCE.md).

GitHub Actions собирает отладочный APK без моделей. Эмуляторный workflow «Real offline Russian ASR (x86_64)» (инструментальные тесты, UI-сценарий записи/импорта/экспорта, установка комплекта моделей) с 0.3.10 снова зелёный на API 34 и 35 ([прогон](https://github.com/Ai-b0ss/nuclear-neurostenographer/actions/runs/42318026836)); API 33 падает на таймауте загрузки эмулятора раннера.

## Приватность

Нет разрешения INTERNET; звук и стенограммы обрабатываются локально. Не загружайте в репозиторий личные записи и ключи; крупные модели поставляются отдельно от исходников.

## История

До 0.3.3 проект прошёл путь от CTC-модели и pyannote + ERes2Net (C0) к A3 + Nemotron C2; эти этапы и все промежуточные измерения — в [docs/PROGRESS.md](docs/PROGRESS.md) и [docs/DECISION_REGISTER.md](docs/DECISION_REGISTER.md).

### Оценка времени на коротких записях

Старая `AudioProcessingClock` для файлов длиннее 20 минут **не была потеряна при merge**: она вошла в main через PR #44. В новой локальной ветке добавлена `ShortProcessingEta` для обычных файлов: после первого завершённого этапа отображается приблизительное оставшееся время по монотонным временным меткам и реальным промежуточным результатам. При задержке этапа больше прогноза оценка снимается вместо ложного «00:00». Точный отдельный APK и телефонная приёмка кандидата должны быть указаны отдельно; в опубликованном 0.3.17 числовой ETA показывался **только для длинных файлов**.
